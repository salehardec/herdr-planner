# Herdr Planner — дизайн панели

> **Плоская панель заменена 3D-миром (PLN-7).** Этот макет остаётся историей:
> семантика статусов, цветов и действий перенесена в мир, см.
> [`world.md`](world.md). Новые снимки — `screenshots/world-*.png`.

Макет: [`herdr-planner.html`](herdr-planner.html) — один файл, без зависимостей, открывается прямо в браузере
(`chromium design/herdr-planner.html`). Данные тестовые; через 3 секунды после загрузки сам проигрывает **живой сценарий**
(смена статусов, уход и появление карточек, свет по нитям). Если до этого вы уже что-то нажали или написали, он не стартует, чтобы не затереть
ваши действия; «▶ Сыграть сценарий» в панели макета запускает его вручную (с начальными данными). Кнопка «⚙ Макет» внизу слева: тема, данные, чат, herdr, ширина, анимация,
«▶ Сыграть сценарий». В окне этих кнопок нет. `?static` в адресе отключает автопроигрыш, `?calm` — анимацию; оба действуют только на этот визит и в память не пишутся. Выбор в панели макета (тема, данные, ширина…) запоминается в `localStorage`. Снимки — в
[`screenshots/`](screenshots).

Это уже не маленький выпадающий список, а **панель-дашборд**: открывается под значком Herdr Planner в панели Omarchy, 1240 × до 940 px
(на экране поменьше сжимается, ниже 1120 px перестраивается — см. «Адаптация»). Поверхность — *Monitor* (следить за доской) с
*Operate* (одобрить, повторить, ответить) и «консолью» Координатора в центре. Первая, компактная версия макета осталась в истории git
(коммит `04aaaef`).

Референс (`reference-toolbox.png`) дал композицию и настроение: тёмный моноширинный «терминальный ретро», тёплый акцент, центральный
персонаж с консолью, пронумерованные карточки по бокам с мини-визуализацией, нити от центра к карточкам, ленты внизу. Цвет,
шрифт, персонаж и содержание — свои: цвета берутся из темы Omarchy, персонаж нарисован заново, карточки — задачи доски.

## Структура окна

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ HERDR-PROJECTS · ДОСКА          ПРОЕКТОВ  ЗАДАЧ  ЖДУТ ТЕБЯ  ТИХИХ  HERDR  [Полный…↗]│  шапка
│ Herdr Planner                                                                  │
│ 01 ОЧЕРЕДЬ ▬▬   02 ПЛАН И РАБОТА ▬▬   03 РЕВЬЮ ▬▬   04 К ОДОБРЕНИЮ ▬▬   05 СДЕЛАНО │  этапы-фильтры
├───────────────────────────────────────────────────────────────────────────────┤
│ ▸ portal-web PRT   ░░░  ┌───────────┐  ░░░  apicache APC ◂                    │
│  ┌ 01 PRT-12 ● Ждёт ─┐╌╌│ КООРДИНАТОР│╌╌┌─ 07 APC-6 ▲ Упала ┐                   │
│  │ заголовок          │╌╌│  (талисман)│╌╌│ заголовок          │  нити:            │
│  │ строка доски       │  ├───────────┤  │ строка доски       │  Координатор ⇄    │
│  │ ●─●─◉───○───○ [Отв.]│  │ $ вопрос  │  │ ●─●─◉───○───○ [Пов.]│  проект ⇄ карточка│
│  ├ 02 …               │  │ › ответ   │  ├ 08 …               │                   │
│  └ …                  │  │ › _       │  └ …                  │                   │
│   (колонка прокручивается) [чипы статусов] (колонка прокручивается)               │
├──────────────────┬────────────────────┬───────────────────────────────────────┤
│ 01 / ЖУРНАЛ ДОСКИ │ 02 / ЖДЁТ ТЕБЯ      │ 03 / ФОКУС · PRT-12                     │  ленты
│ 073 14:32 APC-7 … │ ⌑ PRT-12 ответить   │ заголовок, строка, вердикт, проверки,   │
│ …                 │ ▲ APC-6 повторить   │ действия, «написать агенту», yazi        │
└──────────────────┴────────────────────┴───────────────────────────────────────┘
```

1. **Шапка** — название, фраза-итог («Три проекта в работе. Ждут тебя: 4.»), счётчики (проектов, задач, ждут тебя), «Тихих»
   (проекты без активных задач скрыты, раскрываются списком), индикатор herdr, «Полный планировщик ↗» (отдельное окно Omarchy).
   Ниже пять **этапов доски** с долей от общего числа: очередь → план и работа → ревью → к одобрению → сделано. Это и обзор, и
   фильтр: клик по этапу гасит остальные карточки (и их нити), второй клик снимает.
2. **Колонки проектов** по бокам. Заголовок проекта сворачивается (свёрнутый показывает сводку глифами). Проекты разложены по
   двум колонкам по числу карточек, самые срочные выше; раскладка запоминается, чтобы проект не прыгал между колонками.
   Под карточками — «Сделано ещё N · показать» (старые завершённые одной строкой).
3. **Ядро** — Координатор (пиксельный талисман, цвет `accent`), под ним консоль-чат, под ней чипы статусов (легенда + фильтр).
4. **Ленты**: *Журнал доски* (нумерованные события, новые появляются сверху), *Ждёт тебя* (очередь действий: что и по какой
   задаче; решённые вычёркиваются и гаснут), *Фокус* (детали выбранной карточки).

### Карточка

```
01 PRT-12  claude/sonnet-5.5                      (● Ждёт тебя)   номер · ключ · агент/модель · значок статуса
Тёмная тема в настройках профиля                                  заголовок, до 2 строк
Вопрос: оставить переключатель в шапке…            6 мин          строка доски · время в статусе (или % и «~N мин»)
●──●──◉──○──○──○            [Ответить] [📁]                       рейка этапов · главное действие · папка (yazi)
      работа
```

- **Номер** 01–… идёт в порядке чтения (левая колонка сверху вниз, потом правая); клавиши `1`–`9` выбирают карточку.
- **Рейка этапов** — мини-визуализация положения на доске: очередь → план → работа → ревью → одобрение → готово. Пройденные узлы залиты,
  жетон со значком статуса стоит на текущем; у «в работе» он смещён вперёд на долю прогресса. Подпись — только у текущего этапа.
- **Действия** — их не больше трёх, главное одно по статусу:

| Статус | Главная кнопка | Команда доски |
|---|---|---|
| ждёт тебя | Ответить (фокус в поле «Написать агенту») | `tell` |
| упала | Повторить | `retry` |
| готова к одобрению | Одобрить → «Мержить в main?» (3,5 с на второй клик) | `approve` |
| план готов | Одобрить план | `approve` |
| на ревью, в работе, сделано | — | |
| в очереди | — (в «Фокусе»: «Запустить сейчас») | `delegate --now` |

  Всегда: значок **папки** — worktree в yazi (у задач в очереди его нет, значка нет). Клик или Enter по карточке — выбрать её:
  детали открываются в ленте «Фокус» (никаких оверлеев), её нить подсвечивается. Там же: «Вернуть ревью агенту» (`review`), «Остановить»
  (`stop`), поле «Написать агенту» (`tell`), «Вкладка агента» (только с herdr).

## Анимации

Всё, что движется, говорит о доске, а не украшает.

| Что | Как | Зачем |
|---|---|---|
| **Нити** Координатор → проект → карточка | SVG по реальным позициям карточек: от талисмана тройной «пучок» тонких кривых к порту заголовка проекта, дальше шина вдоль колонки и ответвление к порту карточки. Пересчитываются при прокрутке, сворачивании, смене размера | показать, что доска связана: кто кому подчинён |
| Бегущие огоньки / кометы по нитям | направление и скорость по статусу (таблица выше): от Координатора — работа и ревью, к нему — всё, что ждёт тебя | видно, где живая работа, а где нужен ты |
| «Думает» | при отправке света уходит по всем трём магистралям, огоньки ускоряются, талисман водит глазами | ответ ещё не пришёл |
| **Смена статуса** | карточка переезжает на новое место (FLIP), значок статуса переворачивается, вокруг расходится кольцо цвета нового статуса, жетон на рейке плавно едет к новому этапу, по нити к Координатору идёт световой пакет, в журнал падает строка с подсветкой, в «Ждёт тебя» пункт вычёркивается и гаснет | понятно, что произошло и где |
| **Появление карточек** | при открытии — каскад по 60 мс; новая задача (её заводит Координатор) — всплывает, к ней идёт световой пакет по нити | |
| **Уход карточек** | карточка не пропадает мгновенно: её копия доигрывает уход, соседи плавно сдвигаются (FLIP), нить к ней гаснет. Три вида (таблица ниже) | понятно, куда делась задача |
| **Дыхание** задач в работе | свечение и рамка карточки, жетон и эквалайзер пульсируют с разной фазой (3,4 с) | отличить живую работу от ожидания |
| Мелочи | мигающий «усик» и глаза талисмана, пинг при ответе, точки «читает доску…» | |

**Что происходит, когда карточка уходит:**

| Случай | Анимация | Куда делась |
|---|---|---|
| **«Сделано» устарело** (свежая «сделано» живёт карточкой недолго; срок задаёт реализация, в макете 9 с после смены статуса) | карточка сжимается и летит в строку «Сделано ещё N · показать», строка коротко подсвечивается, счётчики и чип «сделано» обновляются | в строку «Сделано ещё N» своего проекта |
| **Проект свёрнут** | карточки складываются в заголовок проекта; нити к ним гаснут | остаются за заголовком, разворачиваются каскадом |
| **Задача снята с доски** (отменена, архивирована, Координатор объединил её с другой) | растворяется на месте (уменьшение + размытие), нить втягивается, в журнал падает строка «снята…», выбранная карточка переходит на ближайшую | исчезает совсем; следы — только журнал |
| **Пустая доска** (данные пропали) | то же растворение, каскадом по 45 мс | |
| Остановлена вручную (`stop`) | **не уходит**: меняет статус на «Упала» («Остановлена вручную») и ждёт «Повторить» | остаётся карточкой |

Если проект остался без единой карточки (все устарели), он уходит в «Тихие проекты». Кадр ухода «сделано» в строку — `screenshots/card-exit.png`.

Токены движения: `--m-fast` 0,14 с, `--m-med` 0,35 с, `--m-slow` 0,8 с (рейка, полосы этапов), `--m-ease` `cubic-bezier(.2,.7,.2,1)`,
`--m-breath` 3,4 с. Все анимации — CSS и Web Animations API, без библиотек.

**`prefers-reduced-motion: reduce`** (и ручное «Анимация: Выкл» в макете): все `animation` и `transition` отключены; карточки
переставляются, появляются и уходят сразу (копии-призраки не создаются), нити остаются статичными (толщина и яркость по статусу), пакеты света и FLIP не запускаются. Сценарий при этом
работает — состояния меняются, просто без движения. Смысл не теряется: статус всё так же виден по значку, подписи и рейке.

## Самостоятельность: без herdr и без herdr-gpui

Окно живёт отдельно от herdr.

- **Данные идут напрямую от herdr-projects** (`herdr-projects list --json`, `details`) и его папки данных. Вкладок herdr-gpui нет.
- **Команды тоже его**: `approve`, `retry`, `review`, `tell`, `stop`, `delegate --now`, `coordinator tell` — без запущенного herdr (TUI).
- Недоступны без herdr ровно два действия: **«Вкладка агента»** и **«Показать проект в пространстве herdr»**. В макете: в шапке
  индикатор «не запущен» (клик — пояснение, что работает, а что нет), кнопка вкладки агента в «Фокусе» пунктирная и неактивна, под ней
  строка «Вкладка агента — только в herdr…», клик даёт тост «Нужен herdr: он не запущен». Когда herdr запущен — зелёная точка, кнопка активна.
- Файлы — **yazi**, отдельным окном терминала (`xdg-terminal-exec yazi <папка>`), своего просмотрщика нет. Значок папки на карточке =
  worktree задачи; в «Фокусе» ещё «Отчёты и заметки» (`~/.herdr-projects/reports/<repo>/<n>/`). Для задачи в очереди worktree ещё нет —
  кнопка неактивна, тост объясняет. Не требует herdr. Точные пути брать из `herdr-projects details`: в макете они условные.
- «Полный планировщик» — отдельное окно Omarchy, не вкладка.

> Проверить при реализации: может ли Координатор доски стартовать без herdr. Если нет — состояние «Ошибка» чата должно говорить об
> этом прямо.

## Цвета: из темы Omarchy

Источник — `~/.local/state/omarchy/current/theme/colors.toml` (имя темы — рядом, `theme.name`; сами темы лежат в
`/usr/share/omarchy/themes/*` и `~/.config/omarchy/themes/*`). Служба читает ключи и отдаёт странице как CSS-переменные слоя 1;
слой 2 считается чистым CSS (`color-mix`), так что тема в коде нигде не перечисляется. Смена темы перезаписывает файл — следить за ним
(inotify или опрос раз в несколько секунд) и обновлять переменные без перезагрузки; нити пересчитывать нужно только при смене
геометрии, цвета они берут из переменных сами (переход цвета 0,35 с).

**Слой 1, «сырой»**: `--c-bg` ← `background`, `--c-bg-dark` ← `dark_background`, `--c-bg-darker` ← `darker_background`,
`--c-bg-light` ← `lighter_background`, `--c-fg` ← `foreground`, `--c-fg-bright` ← `bright_foreground`, `--c-muted` ← `muted`,
`--c-accent` ← `accent`, `--c-sel` ← `selection`, `--c-red|yellow|green|cyan|blue|magenta` ← одноимённые ключи,
`--c-border-a/b` ← два цвета `hyprland_active_border` (нет ключа — оба равны `accent`). `mode = "light|dark"` → `data-mode`.

**Слой 2, токены окна**:

| Токен | Формула |
|---|---|
| `--pl-bg` | `background` (как у всплывающих окон оболочки Omarchy) |
| `--pl-text` / `--pl-title` | `foreground` / `bright_foreground` |
| `--pl-dim` / `--pl-faint` | `foreground` 93 % / 84 % к фону (светлые темы 98 % / 94 %) |
| `--pl-tile` / `--pl-raised` | `foreground` 5 % / 9 % к фону |
| `--pl-line` / `--pl-dot` | `foreground` 15 % к фону / 9 % на прозрачном (точечная сетка сцены) |
| `--pl-accent` / `--pl-on-accent` | `accent` / `background` (талисман, кнопка отправки, значок в панели, полосы этапов) |
| `--s` на статусе | цвет статуса из таблицы выше |
| `--s-fill` / `--s-line` | `--s` 15 % / 38 % к фону (значок, чип; подсветка карточки — 7 %) |
| `--s-ink` (текст значка, жетон, главная кнопка, нить) | `--s` 70 % + `foreground` (светлые темы — `--s` 18 %); у «очереди» и «сделано» — `--pl-dim` |

Рамка окна — градиент `hyprland_active_border`. Шрифт — системный моноширинный Omarchy (JetBrainsMono Nerd Font, 12 px), своего окно не
приносит. Размеры в реализации лучше брать из `shell.toml` темы (`[font] base-size`, `[spacing]`); в макете они зафиксированы.

**Проверено** на пяти темах (Americano Night/Day, Tokyo Night, Catppuccin Latte, White). Скрипт обходит **каждый элемент окна с собственным
текстом** (21 тыс. проверок), берёт вычисленный цвет, сводит полупрозрачные слои фона и требует не ниже **4,5 : 1**. Он прогоняет состояния:
обычное, herdr запущен, чат пустой / думает / ответ / развёрнут / ошибка, нет связи, пустая доска, оба всплывающих пояснения, поле ввода с
текстом (кнопка отправки «зажжена») и по очереди все 11 карточек выбранными (все варианты «Фокуса»). Результат: 0 нарушений. Акцент и красный
как **цвет текста** (`›`, «развернуть», ошибка, «Остановить») в светлых темах затемняются (`--pl-accent-ink`, `--pl-danger`), текст на акцентной
кнопке в светлых темах — почти белый (`--pl-on-accent`). Исключены намеренно приглушённые элементы: недоступные кнопки (`aria-disabled`),
карточки при потере связи и погашенные фильтром, вычеркнутые пункты «Ждёт тебя», призраки уходящих карточек. Состояния наведения/фокуса отдельно
не проверялись. В светлых темах запас у жёлтого и пурпурного самый тонкий — при новых темах смотреть их первыми.

## Чат Координатора

Консоль в центре: `$` — твоя последняя реплика, `›` — ответ Координатора, внизу строка ввода `› …` + «↵ отправить». Это
`herdr-projects coordinator tell`.

- **Enter** — отправить, **Shift+Enter** — новая строка (до 4 строк), **↑** в пустом поле — вернуть последнее сообщение, **Esc** — очистить
  и снять фокус, **/** — в поле из любого места. При открытии окна фокус в поле.
- Кнопка отправки «зажигается» (accent), когда есть текст. Отправлять можно всегда, и пока Координатор думает: сообщения идут ему по очереди.
  **Черновик не теряется**: любое обновление данных (смена статуса, пришёл ответ) перерисовывает журнал консоли, но не поле ввода.
- История не копится: показан **только последний обмен** — реплика и ответ, ответ свёрнут до 3 строк, «развернуть ▾» / «свернуть ▴». Как в
  консоли референса, обмен стоит **над** строкой ввода, а не под ней (так было в первом задании; после отзыва выбрана консоль). Поменять
  местами — одна правка раскладки консоли, состояния и поведение не меняются. Ключи задач в ответе (`PRT-16`) — кнопки: выбирают карточку.
- Состояния: **пусто**, **думает** (точки; талисман водит глазами, по нитям идёт свет, огоньки ускоряются), **ответ**, **развёрнут**,
  **ошибка** («Не получилось передать…», «отправить ещё раз»; введённое не теряется). Если Координатор завёл задачу — карточка появляется
  (по нити идёт свет), в журнале строка.

## Состояния окна

| Состояние | Что видно |
|---|---|
| обычное | как в снимках |
| пустая доска | счётчики 0, колонки пусты («Всё тихо…»), нитей нет, «Ждёт тебя» и «Фокус» — подсказки, талисман ждёт |
| нет связи с доской | красная плашка «Доска не отвечает — показаны данные от 14:20, действия выключены» + «Повторить»; карточки приглушены, **кнопки действий и поле «Написать агенту» неактивны** (`aria-disabled`, клик даёт тост), отправка в чат уходит в «ошибку»; открыть файлы (yazi) можно — это локально |
| herdr не запущен / запущен | см. «Самостоятельность» |
| фильтр (чип, этап) | несовпавшие карточки и их нити гаснут, структура не прыгает |
| значок в панели | число = ждут тебя (ждёт, упала, к одобрению, план готов); акцентная пилюля, если больше 0, иначе серая |

**Адаптация.** Колонки: боковые тянутся, ядро — 390–440 px. Ниже 1120 px окно «стекается»: ядро сверху, под ним две колонки, ленты друг под
другом, окно прокручивается целиком. Ниже 860 px («узко», в макете 620): колонки по одной, шапка в одну колонку (счётчики переносятся, этапы
в два столбца, пояснения — в потоке под ними); **нити в этом режиме выключены** (статус остаётся виден по значку и рейке).

## Клавиатура

Фокус при открытии — в поле чата. `/` — в поле; `1`–`9` — выбрать карточку по номеру; `↑`/`↓` — предыдущая/следующая; Tab — по карточкам и
кнопкам; Enter на карточке — выбрать; Esc закрывает всплывающее пояснение (herdr / тихие проекты). Любое нажатие клавиши или клик в окне считается «пользователь начал работать» (см. автосценарий).

## Что намеренно не сделано

Своего просмотрщика файлов и редактора, вкладок herdr-gpui; списка всех завершённых задач (для этого «Полный планировщик»); настроек и
групп проектов — окно показывает, отвечает и подсказывает, что ждёт тебя. Нити — украшение с содержанием, но не единственный носитель
смысла: без них (стек, reduced-motion) всё читается.
