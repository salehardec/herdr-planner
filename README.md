# Herdr Planner

«Планировщик проектов» для [herdr-projects](https://github.com/salehardec): локальное веб-приложение, которое
открывается во вкладке herdr-gpui, отдельным окном Omarchy или в любом браузере и выглядит в теме herdr-gpui.
Преемник плагина Tern [herdr-dashboard](https://github.com/salehardec/tern_herdrplugin) (0.17.1): его README — эталон
поведения, логика переносится оттуда по этапам.

**Этап 1**: каркас, тема, список проектов, группы, следование за активным пространством herdr, перенос
сохранённого состояния плагина. **Этап 2**: карточка проекта — треды с git-строками и бейджами моделей,
задачи из TASKS.md с «Решить» / «Не решать» / «Задать вопрос», фильтр карточки. **Этап 3**: экран настроек
(дешёвый агент, автопроверка, автопредложение, группы), автопроверка актуальности задач, автопредложение групп,
форма «Новый проект». **Этап 4 (этот)**: упаковка — установка одним скриптом, служба `systemd --user`, ярлык и
горячая клавиша Omarchy.

## Запуск

```sh
cargo run --release            # http://127.0.0.1:7117
cargo run -- --port 8080       # другой порт
herdr-gpui browser open localhost:7117   # вкладка в herdr-gpui (на Linux-сборке без вкладок — системный браузер)
```

Один бинарник, страница встроена в него (`include_str!`), внешних ресурсов и CDN нет. Слушает только `127.0.0.1`.

- Порт: `--port N`, иначе `HERDR_PLANNER_PORT`, иначе `port = N` в `~/.config/herdr-planner/config.toml`, иначе `7117`.
- Корень проектов: `--root DIR`, иначе `HERDR_PROJECTS_ROOT`, иначе `root = "…"` в том же config.toml, иначе `~/.herdr-projects`.
- Состояние (группы, настройки, вопросы-ответы, отметки «отправлено», вердикты актуальности):
  `~/.local/state/herdr-planner/state.json` (`$XDG_STATE_HOME`).
- `HERDR_PLANNER_FRESH_DEBOUNCE_SECS` — сколько новый коммит в main ждёт перед повторной проверкой задач (60 с);
  `HERDR_PLANNER_OPEN_WAIT_SECS` — сколько «Решить» ждёт запуска координатора (45 с); `HERDR_BIN=/путь` — `herdr`.
- `herdr-projects` ищется в `PATH`; `HERDR_PROJECTS_BIN=/путь` переопределяет.

Постоянная установка (служба `systemd --user`, ярлык и горячая клавиша Omarchy) — раздел «Установка».

## Установка

Без `sudo` и системного пакетного менеджера; всё лежит в домашней папке. Нужны `cargo` (или `mise` с `rust@stable`),
`systemd --user`; для клавиши — Omarchy на Lua-конфиге Hyprland (`~/.config/hypr/bindings.lua`), `hyprctl` и `jq`.

```sh
scripts/install.sh              # собрать release, поставить, включить службу, ярлык и клавишу
scripts/install.sh status       # что стоит, включена ли служба, отвечает ли порт
scripts/install.sh uninstall    # убрать всё установленное
```

Что и куда ставится:

| Что | Куда |
|---|---|
| бинарник и открывалка | `~/.local/bin/herdr-planner`, `~/.local/bin/herdr-planner-open` |
| служба | `~/.config/systemd/user/herdr-planner.service` (из `packaging/`, включена и запущена) |
| ярлык приложения | `~/.local/share/applications/herdr-planner.desktop`, значок `…/icons/hicolor/scalable/apps/herdr-planner.svg` |
| клавиша | `~/.config/hypr/herdr_planner.lua` и один помеченный блок в `~/.config/hypr/bindings.lua` |

**Обновление** — тот же `scripts/install.sh` после `git pull`: пересобирает, подменяет бинарник (через переименование, работающий
файл не затирается) и перезапускает службу. Группы, настройки и ответы (`~/.local/state/herdr-planner`, `~/.config/herdr-planner`)
не трогаются; `uninstall` их тоже оставляет. Флаги: `--no-build` (взять уже собранный `target/release/herdr-planner`),
`--no-service`, `--no-hypr`, `--key "SUPER + ALT + P"`. `HERDR_PLANNER_BIN_DIR` — другая папка для бинарников, `HERDR_PLANNER_SRC` — другой собранный бинарник.

**Служба.** `herdr-planner.service` слушает только `127.0.0.1:7117` (порт — `config.toml` или `HERDR_PLANNER_PORT`, см. «Запуск»),
перезапускается при сбое (`Restart=on-failure`, пауза 2 с), стартует вместе с пользовательской сессией systemd. Вывод — в journal:

```sh
systemctl --user status herdr-planner
journalctl --user -u herdr-planner -f
systemctl --user restart herdr-planner
```

В юнит записывается `PATH` с папками, где на момент установки нашлись `herdr-projects`, `herdr`, `claude` и `git`: у служб
systemd нет `PATH` оболочки. Если эти программы переехали, запусти установку ещё раз. Запущенный вручную `herdr-planner`
занимает порт — останови его (`pkill -x herdr-planner`), иначе служба не поднимется.

**Открытие** (`herdr-planner-open`, его вызывают ярлык и клавиша): запускает службу, если она стоит, затем

1. вкладка herdr-gpui — `herdr-gpui browser open localhost:7117`; на Linux-сборке без вкладок эта команда сама отправляет
   страницу в системный браузер и завершается успехом — это считается открытием;
2. иначе окно Omarchy (`omarchy-launch-or-focus-webapp`: уже открытое окно получает фокус, окно ищется по заголовку страницы);
3. иначе `xdg-open`.

Форсировать способ: `herdr-planner-open --tab | --window | --browser` или `HERDR_PLANNER_OPEN=tab|window|browser`.

**Клавиша Hyprland.** `scripts/install.sh` выбирает первую свободную из `SUPER + ALT + P`, `SUPER + SHIFT + H`,
`SUPER + SHIFT + L`, `SUPER + SHIFT + T`, `SUPER + SHIFT + Z`, сверяясь с `hyprctl binds`; своя — `--key "SUPER + …"` (занятая
отклоняется). Привязка лежит в отдельном файле `herdr_planner.lua`, в `bindings.lua` дописан только блок между
`-- >>> herdr-planner (scripts/install.sh) >>>` и `-- <<< herdr-planner <<<` с `pcall(require, …)` — ошибка в нашем файле не
ломает конфиг. Повторная установка блок не дублирует и выбранную клавишу сохраняет; `uninstall` вырезает только свой блок.
Проверить: `hyprctl binds | grep -B6 -A3 "Herdr Planner"` или `SUPER + K`.

## Архитектура

```
src/main.rs        запуск: состояние → тема → фоновые циклы → HTTP на 127.0.0.1:PORT
src/config.rs      порт, корень, XDG-пути
src/app.rs         общее состояние сервера: снимок списка, сохранённое состояние, тема, активное пространство, шина событий
src/poller.rs      фоновые циклы: список проектов (20 с, или по запросу), активное пространство herdr (3 с), файлы темы (2 с)
src/sources/       источники данных — чистые разборщики + неблокирующий запуск команд (tokio::process)
  list.rs            `herdr-projects list --all`
  threads.rs         `herdr-projects thread list <slug> --json`; слова для групп и `note` herdr
  project_md.rs      PROJECT.md: шапка между `+++`, name/goal/[[repos]]
  tasks.rs           TASKS.md: задачи, владельцы `(…)`, треды ` · t-NNNN`, заметки под задачей
  workspace.rs       `herdr workspace list` → метка активного пространства
  git.rs             git треда: скрипты `sh` (ветка, коммиты, diff, не закоммичено, трейлеры) и их разбор
  models.rs          бейджи моделей: профиль (`profile resolve`) и трейлеры `Co-Authored-By`
  profiles.rs        `herdr-projects assignable` → профили для «Решить»
  report.rs          итог завершённого треда из `threads/t-NNNN.md`
src/model.rs       чистая логика списка: сортировка, чипы, фильтр, группы, сопоставление пространства с проектом
src/store.rs       state.json: группы, настройки (таблица `SETTING_DEFS`), Q&A, sent, fresh (формат — как `dash.save` плагина)
src/import_tern.rs перенос состояния плагина из daemon.state Tern при первом запуске
src/theme.rs       тема herdr-gpui → CSS-переменные
src/agent.rs       слой «дешёвый агент» (Haiku / DeepSeek через omp): команды и запуск; им пользуются «Задать вопрос», проверка актуальности и раскладка по группам
src/jsonscan.rs    JSON в ответе агента среди текста и ``` (общий разбор для проверки и раскладки)
src/fresh.rs       автопроверка актуальности задач: вердикты, доказательство «сделано», решение «пора ли», кеш по (текст, коммит main)
src/suggest.rs     автопредложение групп: запрос, разбор ответа (строки / объекты / обёртки), «Разложить заново»
src/newproject.rs  форма «Новый проект»: обзор папок, дополнение пути, машины, профили, `herdr-projects new`
src/cards.rs       данные карточки: кеш git / профилей / трейлеров, фоновые чтения, ворктри в herdr
src/actions.rs     «Решить» / «Не решать» (координатору), «Задать вопрос» (агенту), тексты запросов
src/api.rs         HTTP: страница, JSON API, SSE, защита от чужих сайтов (Host / Origin)
web/               страница: index.html, app.css, app.js (список), card.js (карточка), settings.js (настройки и группы),
                   new.js (форма «Новый проект»), util.js (общее) — встраиваются в бинарник
scripts/ui-check.mjs    проверка страницы в headless Chromium
scripts/fixture.mjs     мир для проверок: проекты, git-репозитории, поддельные herdr-projects / herdr / claude
scripts/run-checks.sh   всё вместе: cargo test + страница на фикстуре
```

Поток данных: `poller` раз в 20 с вызывает `herdr-projects list --all`, дочитывает PROJECT.md, `inbox/` и `threads/`
каждого проекта, кладёт снимок в `App` и шлёт событие `snapshot`; страница держит один `EventSource` на
`/api/events` и перерисовывается. Никаких блокирующих вызовов в обработчиках HTTP: команды идут через
`tokio::process` с таймаутом, чтение папок — в `spawn_blocking`.

### HTTP API

| Метод и путь | Что делает |
| --- | --- |
| `GET /` `/app.css` `/app.js` | страница |
| `GET /api/snapshot` | проекты, группы, настройки, активное пространство, версия |
| `GET /api/theme` | тема (см. ниже) |
| `GET /api/events` | SSE: `theme` и `snapshot` сразу, затем `snapshot` / `theme` / `workspace` / `card` (`{slug}`: карточку стоит перечитать) / `solve` (`{slug,task,stage}`) |
| `POST /api/refresh` | обновить список сейчас |
| `POST /api/groups` | `{op:"assign", slug, name}` · `{op:"add", name}` · `{op:"fold", name, folded?}` · `{op:"toggle", on?}` · `{op:"rename", name, to}` · `{op:"move", name, delta}` · `{op:"delete", name, to?}` · `{op:"resort"}` |
| `POST /api/settings` | `{key, value}` — одна настройка (значение проверяется по `SETTING_DEFS`); снимок и событие `snapshot` приходят следом |
| `POST /api/action` | `{kind:"focus"\|"open", slug}` → `herdr-projects focus` / `open` |
| `GET /api/project/{slug}` | карточка: проект, задачи (с заметками), `fresh` (вердикты, идёт ли проверка, ошибка), треды (git-строка, бейджи, итог, поиск), ответы `qa`, отметки `sent` |
| `GET /api/project/{slug}/thread/{id}` | раскрытый тред: git целиком (diff --stat, 5 коммитов, не закоммичено) |
| `POST /api/project/{slug}/thread/{id}/worktree` | `herdr worktree open --path ВОРКТРИ --focus` (путь берётся из записи треда, не от страницы) |
| `GET /api/project/{slug}/assignable` | профили для «Решить» (`herdr-projects assignable`, кеш 10 минут) |
| `POST /api/project/{slug}/solve` | `{task, profile?}` → координатору; проект не открыт — `open` и повтор раз в 2 с до 45 с |
| `POST /api/project/{slug}/remove` | `{task, fresh?}` → координатору «удали из TASKS.md»; с `fresh` в текст идёт вердикт проверки актуальности (404 нет задачи, 409 её ведёт тред) |
| `POST /api/project/{slug}/fresh-keep` | `{task}` — «Оставить»: отметка спрятана до нового коммита в main (409, пока проект не проверялся) |
| `POST /api/project/{slug}/ask` | `{task, question}` → дешёвый агент; ответ приходит событием `card` |
| `GET /api/new/options` | форма «Новый проект»: `{machines, profiles, last_dir}` (`herdr machine list --json`, `herdr-projects profile list`; не прочиталось — `null`) |
| `GET /api/browse?path=&start=` | подпапки (без скрытых и файлов; `.git` — «репозиторий»); с `start` путь поля — отправная точка, ищется первая читаемая папка |
| `GET /api/complete?path=` | дополнение пути по `tab` в поле «Папка» |
| `POST /api/new` | `{name, goal, repos:[{path, machine}], thread_profile, coordinator_profile}` → `herdr-projects new` (после него страница открывает проект) |

### Фронтенд: почему без фреймворка

Состояние страницы маленькое (фильтр, чип, сортировка, подсветка, открытый проект, у карточки — вкладка, фильтр,
выбранная строка и задача, у настроек — строка и правка группы, у формы — поля), вид — список, карточка и два экрана
поверх них (настройки, «Новый проект»). Поэтому страница — обычные ES-модули с JSDoc-типами
(`// @ts-check`; `npx -p typescript tsc --noEmit --allowJs --checkJs --target es2022 --module es2022
--moduleResolution bundler --lib es2022,dom,dom.iterable web/*.js` проверяет типы),
без сборки: `cargo build` — единственный шаг, страница встраивается как есть. Карточка стала отдельным модулем
`card.js`, настройки и форма — `settings.js` и `new.js`, у каждого своё состояние, но экран по-прежнему один без
независимых виджетов, поэтому сборщик и фреймворк по-прежнему не нужны. Весь экран перерисовывается целиком; поля ввода, каретка и прокрутка списка переживают
перерисовку (`render()` в `app.js`).

Горячие клавиши не зависят от раскладки: буква берётся по физической клавише (`ч` на клавише X — это `x`),
в полях ввода клавиши остаются как набраны.

Логика списка (сортировка, чипы, фильтр, группы) есть и в `src/model.rs` (эталон, покрыт тестами; группы — и
работа сервера: правка, перенос при удалении, автопредложение), и в `app.js` (чтобы фильтр и подсветка не ходили на сервер).
Менять — в обоих местах.

## Откуда тема

herdr-gpui не хранит файлы тем: встроенные (Default, Nord, Dracula, Catppuccin Mocha, Catppuccin Latte) — палитры
в его исходниках (`crates/herdr-gpui/src/config/theme.rs`), и `src/theme.rs` несёт те же значения. Что выбрано,
читается из конфигов `~/.config/herdr/`: `config-gpui.local.toml` (выбор пользователя) поверх `config-gpui.toml`
(умолчания), таблицы сливаются по ключам, как в herdr-gpui:

- `theme = "Nord"` — встроенная тема;
- `theme = "Follow Herdr"` — тема демона herdr из `~/.config/herdr/config.toml` (`[theme] name`, `auto_switch`,
  `light_name`/`dark_name`, `[theme.custom]` с переопределениями `panel_bg`, `accent`, …): палитры UI herdr
  (`herdr_settings/palette.rs`) перенесены в `theme.rs`;
- имя темы Ghostty — файл ищется в `~/.config/herdr/themes`, `~/.config/ghostty/themes`, `$GHOSTTY_RESOURCES_DIR/themes`,
  `~/.local/share/ghostty/themes`, `/usr/share/ghostty/themes` (формат Ghostty: `background`, `foreground`,
  `cursor-color`, `palette = N=#rrggbb`); `~/путь` и абсолютный путь — тоже;
- `theme = "light:A,dark:B"` — обе стороны отдаются странице, она выбирает по `prefers-color-scheme` и следит за сменой.

Производные цвета считаются как в GUI: `surface`/`active`/`muted` — смешение фона и текста (5 / 12 / 55 %),
акцент — `palette[5]`, `accent-wash` — 22 % акцента на поверхности, `contrast = "high"` сдвигает `active`.
Шрифты — `[ui]` и `[terminal]` тех же файлов (`family`, `size`); установленные шрифты не проверяются, в CSS
стоит запасной стек. Файлы темы опрашиваются по mtime каждые 2 с, изменение шлёт событие `theme` — смена
темы в herdr-gpui подхватывается без перезапуска. Если тему прочитать нельзя, показывается палитра Default и
в `/api/theme` поле `error` говорит почему.

CSS-переменные страницы: `--bg --fg --surface --active --muted --subtext --accent --accent-wash --border --sidebar
--cursor --black … --white --bright-*`, `--font-ui --font-mono --size-ui`.

## Список проектов

Паритет с плагином 0.17.1 (см. его README, раздел «Список проектов»):

- Заголовок «Планировщик проектов · N проектов · vX.Y.Z», «⚙ Настройки» (`,`), «обновлено … ↻» (клик — обновить).
- Строка управления: фильтр (`/`), чипы Все / Ревью / Входящие / Пауза с числами (`1`–`4`), «⇅ новые / внимание» (`s`),
  «▦ группы вкл / выкл» (`g`), «+ Проект» (`n`, форма — «Новый проект» ниже).
- Строки: иконка состояния (по счётчикам: 🔔 ждут, ☑ ревью, ✖ блок; иначе ◉ / ⏸ / ▣), имя, «пауза / архив», «авто» у
  группы от агента, справа «N ждут», «N ревью», «N вход.», «сделано/всего»; вторая строка — цель из PROJECT.md.
- `↑` / `↓` подсвечивают (заголовки групп тоже), у подсвеченной строки справа её клавиши; одиночный клик подсвечивает,
  двойной открывает; `enter` открывает проект или сворачивает группу; `←` / `→` сворачивают / разворачивают группу;
  `f` — `herdr-projects focus`, `o` — `herdr-projects open`, `r` — обновить, `?` — все клавиши, `esc` — сбросить
  фильтр и чип, затем подсветку; из открытого проекта `esc` возвращает в список с подсвеченным проектом.
- Фильтр: `↑` / `↓` выходят из поля и двигают подсветку, текст остаётся; `enter` открывает первый найденный.
- Группы: заголовок `▾` / `▸`, имя, число, сводка внимания; свёрнутая показывает имена проектов приглушённо;
  «Прочее» в конце; при фильтре пустые группы скрыты. `t` на проекте — выбор группы (группы, «новая группа…», «без группы»),
  ручной выбор не перезаписывается автоматикой. Всё хранится в state.json.
- Сортировка «новые» — по номеру новейшего треда; «внимание» — ждут/ревью/входящие, затем активные.

## Карточка проекта

Паритет с плагином 0.17.1 (раздел «Детальный вид»): `enter` на проекте (или смена пространства herdr) открывает карточку.

- Шапка: «← Назад», имя, «⚙» (настройки, `,`), «Фокус F», «Открыть O», «обновлено … ↻». «Траты агентов» (`u`) в планировщик
  не переносятся (отдельная утилита): кнопки и клавиши нет.
  Под ней «Цель» и «Репозитории» (удалённый — с `@машина`), шкала «N из M сделано · T тредов» (тредов и задач вместе).
- Вкладки «Сделать / Сделано» (`tab`, `1` / `2`), фильтр `/` (находит по id, названию, статусу, ветке, итогу, модели,
  профилю, агенту, трейлерам, словам «сбой запуска» / «не запустился»; `↑` / `↓` выходят из поля, текст остаётся).
  В «Сделать» — открытые треды: сбой запуска первым, затем ждут вас, ревью, вливаются, в работе, простаивают (внутри
  группы новые выше), потом открытые задачи в порядке TASKS.md; в «Сделано» — закрытые треды (новые выше) и `[x]`.
- **Тред.** Строка: значок группы, `t-NNNN`, название; справа бейдж модели, слово состояния, `▸` / `▾`. Под ней git-строка
  `⎇ ветка · N коммитов · F файлов +add −del · ● не закоммичено: N · PR #n слит`; «ворктри удалён», «без ворктри»
  (вкладка, чекаут), «изменений нет». Коммиты и diff — против базы треда (`origin/main`, нет её — `main` / `origin/master` /
  `master`), правки — по `git status`.
  Статусы herdr по-человечески: группа («ждёт тебя», «ревью», «вливается», «в работе», «простаивает»), `note`
  («пейн закрыт», «агент простаивает», «PR слит», «закрыт вручную», «закрыт автоматически», «агента нет»…), у работающего
  `~N%`. Сбой запуска — красным «✕ сбой запуска: текст»; у закрытого треда тихо «✕ не запустился».
  `↑` / `↓` подсвечивают строки, `enter` или клик раскрывают блок: итог из `threads/t-NNNN.md`, статус, ветка, база, ворктри,
  PR (ссылка), «Запуск» (агент · профиль · модель · effort · @машина), «Модель» с источником, затем `git diff --stat`
  (до 12 файлов и итог), последние 5 коммитов, файлы не закоммичено (до 8). `w` (или «Открыть ворктри») —
  `herdr worktree open --path … --focus`: ворктри открывается в herdr и получает фокус.
- **Бейджи моделей.** «Sonnet 5.5», «Opus 5.5», «Haiku 5.5», «Fable 5.1», «DS Flash», «DS Pro», неизвестная — как есть (до
  18 знаков); цвет по семейству, название всегда рядом. Работающий тред — модель его профиля (`herdr-projects profile
  resolve`, `--model` / `--effort`, `profile_args` треда сильнее; ответ кешируется на 10 минут; профиль удалённой машины
  и не раскрывшийся показаны по имени). Завершённый — модели из `Co-Authored-By` его коммитов (ветка над базой, живая ветка
  в репозитории, слитый squash-коммит PR `… (#N)`, коммиты слитого merge-коммита; люди пропускаются), нет трейлеров —
  модель профиля приглушённо и пунктиром.
- **Задачи.** Клик или `enter` на строке выбирает задачу: под списком панель с заметками из TASKS.md и действиями.
  «Решить» (`enter`) — `herdr-projects coordinator prompt <проект> --text-file -` с «Реши задачу … Делегируй её треду с
  профилем X…» и ответами на вопросы; «профиль ▾» — «на выбор координатора» и профили из `assignable` (чужих машин —
  `профиль@машина`). Проект не открыт (ошибка содержит «`open `») — «Открываю проект…»: `herdr-projects open`, затем повтор
  раз в 2 с до 45 с (`HERDR_PLANNER_OPEN_WAIT_SECS`). При отказе и таймауте выбор остаётся. «Не решать» (`x`) спрашивает
  «Убрать из бэклога? [Да] [Нет]» (`y` / `n`), «Да» шлёт координатору «удали её из TASKS.md»; у задачи, которую ведёт тред,
  кнопки нет. «Задать вопрос» (`?`) — дешёвый агент (настройка «Дешёвый агент», пока Haiku 5.5), только чтение, в папке
  проекта и с локальными репозиториями проекта; ответ markdown под задачей, новые сверху. **TASKS.md приложение не правит.**
- Отметки «отправлено координатору» / «просьба убрать отправлена» и вопросы-ответы хранятся в `state.json` по ключу
  `slug\nтекст задачи` (формат плагина); записи задач, которых нет в прочитанном TASKS.md, удаляются, старые ключи без
  slug переносятся в проект с таким текстом.
- Клавиши: `/` · `tab` / `1` / `2` · `↑` `↓` · `enter` · `w` · `o` · `f` · `r` · `,` настройки · `esc` (снять выбор, затем назад);
  в выбранной задаче `enter` решить, `?` спросить, `x` не решать, `esc` снять выбор.
- git, профили и трейлеры читаются в фоне (не больше 6 git-скриптов и 3 чтений репозитория сразу, `--no-optional-locks`):
  карточка отвечает сразу тем, что в кеше, и событием `card` просит страницу перечитать. Из закрытых тредов git читается у 8
  новейших с живым ворктри, трейлеры — у 60 новейших.
- Отметки автопроверки актуальности (`◐ частично`, `⊘ сделано`) — раздел «Проверка актуальности задач» ниже.

## Проверка актуальности задач

Для открытого проекта дешёвый агент сверяет открытые задачи `TASKS.md` с кодом репозитория (первый репозиторий проекта
без `machine`, существующий на этой машине): один вызов на весь бэклог, на входе путь репозитория, коммит `main`,
`git log` с прошлой проверки и **задачи вместе с их заметками** из TASKS.md, на выходе JSON-массив
`[{"n":1,"v":"actual|partial|done","why":"…","proof":"путь/файла"}]`. Разбор терпит текст и ``` вокруг JSON, объект-обёртку,
числа строкой, русские слова вердикта; мусор вердиктом не становится (ошибка — строка под шкалой, повтор не раньше
чем через 5 минут). Агент только читает (Read/Grep/Glob), сомневаясь отвечает `actual`.

- **«Сделано» только с доказательством в коде.** Вердикт `done` принимается, если в `proof` назван файл репозитория,
  который существует на диске (путь от корня, `путь:строка` допустим, `..` и абсолютные пути не годятся). Нет такого файла —
  вердикт считается `actual` и отметки не даёт. Файл показан в панели задачи («Доказательство в коде»).
- Когда: страница держит карточку открытой и перечитывает её каждые 20 с; на каждом чтении сервер смотрит коммит `main`.
  Новый коммит прячет вердикты старого сразу, а проверка идёт через минуту после последнего изменения
  (`HERDR_PLANNER_FRESH_DEBOUNCE_SECS`); при открытии проекта, если `main` ушёл с прошлой проверки, и для новой или
  переписанной задачи — сразу. Закрытая карточка ничего не проверяет.
- Кеш по (текст задачи, коммит `main`) хранится в `state.json` (`fresh`); записи задач, которых больше нет в прочитанном
  TASKS.md, чистятся.
- Не проверяются: задачи человека (`(me)`, имя, не являющееся профилем: `(Priya Rao)`, `(Bob)`), задачи, которые уже ведёт тред
  (` · t-NNNN`). Профили берутся из `herdr-projects assignable`; пока список не получен, проверяются только задачи без владельца.
- Показ: у актуальных ничего; «◐ частично» / «⊘ сделано» в правой части строки (бейдж только у неактуальных), пока идёт
  проверка — тусклое «…». Клик или `enter` на строке открывает панель задачи: причина, доказательство и кнопки «Убрать» и
  «Оставить». «Оставить» прячет отметку до следующего коммита в `main`; «Убрать» спрашивает «Убрать из бэклога?» и просит
  координатора (с вердиктом в тексте). **Ничего не удаляется само, TASKS.md приложение не правит.**
- Выключается в настройках («Автопроверка актуальности»); включение проверяет открытый проект сразу.

## Настройки

«⚙ Настройки» в списке, «⚙» в карточке, клавиша `,`; `esc` или «← Назад» закрывают. Экран строится из таблицы
`SETTING_DEFS` в `src/store.rs` (ключ, подпись, подсказка, варианты, умолчание) — новая настройка это ещё одна запись;
неизвестное или испорченное значение возвращается к умолчанию.

| Настройка | Варианты | Умолчание |
| --- | --- | --- |
| Дешёвый агент | Claude Haiku 5.5 · DeepSeek Flash (omp) | Claude Haiku 5.5 |
| Автопроверка актуальности | вкл · выкл | вкл |
| Автопредложение групп | вкл · выкл | вкл |

Клавиши: `↑` / `↓` строка · `←` / `→` / `enter` значение · на группе `[` / `]` (или `shift`+`↑`/`↓`) порядок, `enter`
переименовать, `x` удалить (затем `y` / `n`; у группы с проектами `←` / `→` выбирают, куда их перенести) · `a` добавить
группу · `esc` назад. Всё то же — кнопками.

Под настройками карточка «Группы проектов»: порядок групп (↑ ↓), переименование (проекты и «свёрнутость» идут за именем),
удаление, «+ Группа» и «↻ Разложить заново». Удаление пустой группы — «Да» / «Нет»; у группы с проектами: «В группе N проектов.
Перенести в: [Прочее ▾]»: в другую группу проекты переходят ручным выбором, в «Прочее» — как были (ручной выбор остаётся
ручным, «авто» остаётся догадкой). «Разложить заново» стирает только «авто»-назначения и просит агента ещё раз, даже при
выключенном автопредложении. Название «Прочее» занято.

## Автопредложение групп

Проекту без группы дешёвый агент подбирает группу по имени и цели (`goal` из PROJECT.md). Один вызов на все проекты без
записи, один раз на проект (новый проект получает группу при появлении в списке — сервер проверяет это после каждого
чтения списка); ответ — JSON `[{"slug":"…","group":"…"}]`, разбор терпит ``` и текст вокруг, объект «slug → группа»,
«группа → [slug]» и обёртки; мусор группой не становится (ошибка — тихая строка в настройках, повтор не раньше чем через
5 минут). Агент выбирает из списка групп и называет новую (не больше трёх за раз) только если проект явно ни к одной не
подходит. Автоназначение помечено в строке «авто»; ручной выбор не перезаписывается. Стартовый набор: Omarchy · ЯНАО ·
ИИ-инфраструктура · Агенты и herdr · Личное. PROJECT.md проектов не меняется.

## Новый проект

`n` или «+ Проект» (и «Новый проект…» в конце списка) открывают форму; поля — как у `herdr-projects new`:

- **Папка** — поле с «Обзором»: `↓` в поле (или «Обзор») раскрывает под ним подпапки (без скрытых и файлов; папка с `.git` —
  «⎇ репозиторий», не больше 20 строк, окно идёт за подсветкой). `→` или клик заходит в папку, `←` или `..` поднимается и
  подсвечивает ту, из которой вышли, `enter` выбирает (путь в поле, «Название» из имени папки, курсор — в «Название»;
  на `..` — поднимается), `esc` закрывает обзор, `tab` закрывает и идёт дальше. Стартовая папка: путь из поля, иначе папка
  прошлого выбора, иначе `~/Projects`, иначе `~`. `tab` в поле «Папка» сначала дополняет путь.
- **Название** (если не набрано — из имени папки), **Цель**.
- **Машина** под каждой папкой: клик перебирает «локально» → `@машина` → … из `herdr machine list --json` (включённые).
  Нет списка — бейдж открывает поле, имя вводится руками. Для чужой машины «Обзор» и `tab` отключены, путь не раскрывается,
  существование папки не проверяется.
- **«+ ещё репозиторий»** — до 6 строк (`--repo` повторяется); пустая лишняя строка пропускается, машина без папки — ошибка;
  название и слаг берутся от первой папки.
- **Профили** «Треды» и «Коорд.» перебирают допущенные профили из `herdr-projects profile list` (первое значение —
  «как в настройках (имя)», флаг не передаётся). Нет списка — строки профилей нет.
- `enter` создаёт: сервер проверяет входы и запускает `herdr-projects new` (значения вида `--goal=…`, имя после `--`),
  страница открывает проект и запускает его координатора (`herdr-projects open`). `esc` — отмена. Проект с занятым слагом —
  409 «Проект … уже есть». PROJECT.md пишет только `herdr-projects`.

## Следование за пространством herdr

Сервер раз в 3 с спрашивает `herdr workspace list` и берёт метку пространства с `"focused": true` (хвостовой U+2800
убирается). Метка сопоставляется с проектом как в плагине: имя проекта (Name из PROJECT.md, без регистра), иначе slug;
два проекта с одним именем — не сопоставляются. Страница реагирует только на смену (`seq` в событии `workspace`):
открывает карточку проекта; уход в список (`esc`) держится до следующей смены; пока идёт ввод (фильтр, выбор группы),
переключение ждёт и применяется, когда поле закрыто.

## Перенос из плагина Tern

Tern хранит `dash.save` блока внутри `~/.local/state/tern/daemon.state` (бинарный файл) рядом со строкой
`herdr-dashboard.dashboard`. При первом запуске (нет state.json) `import_tern.rs` только читает этот файл, находит
последний JSON-объект с ключами плагина и переносит: группы (список, назначения с пометкой «авто», свёрнутые,
переключатель), настройки, Q&A и отметки `sent` (ключи `slug\ntext`, старые ключи без slug тоже), вердикты
актуальности `fresh`, `last_dir` формы. Источник записывается в `imported_from`. Файл Tern не меняется.

cargo test                       # разборщики, git-скрипты на настоящем репозитории, модели, сортировка/фильтр/группы

                                 # вердикты и доказательство «сделано», решение «пора ли проверять», разбор ответа с группами,

scripts/run-checks.sh [папка-для-скриншотов]   # то же + установщик во временных папках (scripts/check-install.sh)

cargo run &                      # или по отдельности, на живом сервере:
node scripts/ui-check.mjs http://127.0.0.1:7117 [папка-для-скриншотов]

фильтр, открытие карточки и возврат. На живом сервере карточка, экран настроек и форма «Новый проект» (открыть, посмотреть,
закрыть) проверяются только на чтение. С `FIXTURE=DIR` (`run-checks.sh` делает всё сам) всё проверяется целиком на мире
из `scripts/fixture.mjs` — три проекта, настоящие
git-репозитории с ворктри, и поддельные `herdr-projects`, `herdr`, `claude`, которые только пишут в `DIR/log/*.jsonl`, что у них
просили: порядок строк, git-строки, бейджи (профиль, трейлеры ветки и слитого PR, приглушённый), раскрытие, `w`, фильтр и
каретка в нём, раскладка `ч`/`т`, выбор задачи, вопрос (команда агента, текст запроса, markdown без исполнения разметки),

проверки актуальности (вердикты с доказательством, заметки задач в запросе агента, «Оставить», «Убрать» с вердиктом в тексте

добавление / переименование / порядок / удаление групп, перенос проектов при удалении, «Разложить заново» и ручной выбор,
неверные входы), автопредложение для нового проекта, форма «Новый проект» (обзор папок, дополнение `tab`, машины, второй
репозиторий, профили, точные аргументы `herdr-projects new`, открытие проекта, ошибки 400 / 409 / 502). Поддельный
`herdr-projects new` только пишет папку в фикстуру; настоящие проекты, координаторы и боковая панель в проверках не участвуют.
CI нет.

## План этапов

- **Этап 2 — карточка проекта (сделан)**: треды с git-строками (`⎇ ветка · коммиты · файлы · не закоммичено · PR`, неблокирующий
  `git --no-optional-locks`, кеш), бейджи моделей (профиль / трейлеры `Co-Authored-By`), раскрытие треда, `w` — ворктри
  в терминале, сбои запуска, вкладки «Сделать / Сделано», фильтр карточки, задачи с «Решить» (с профилем), «Не решать»,
  «Задать вопрос» через `agent.rs`, отметки `sent` и Q&A по ключу `slug\ntext`. Данные уже отдаёт `GET /api/project/{slug}`.
- **Этап 3 — настройки и агент (сделан)**: экран настроек (`SETTING_DEFS`: дешёвый агент, автопроверка, автопредложение),
  группы (порядок, переименование, удаление с переносом, «Разложить заново»), автопроверка актуальности (`fresh.rs`;
