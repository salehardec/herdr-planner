# Herdr Planner

«Планировщик проектов» для доски [herdr-projects](https://github.com/salehardec): локальное веб-приложение, которое
открывается во вкладке herdr-gpui, отдельным окном Omarchy или в любом браузере и выглядит в теме herdr-gpui.
Преемник плагина Tern [herdr-dashboard](https://github.com/salehardec/tern_herdrplugin) (0.17.1): список проектов, группы,
фильтр, чипы и следование за пространством herdr перенесены оттуда.

**Источник данных — доска herdr-projects**: задачи с ключами (`PLN-1`, на самом деле `<репозиторий>/<номер>`), их стадии, агенты,
ревью, одобрение. Планировщик ничего не решает за доску: он читает её (`herdr-projects list --json`, `details`) и передаёт ей
команды (`approve`, `review`, `retry`, `delegate`, `stop`, `tell`). Проект — это репозиторий доски. `TASKS.md`, треды, координаторы
и `PROJECT.md` прежнего herdr-projects планировщик больше не читает.

## Запуск

```sh
cargo run --release            # http://127.0.0.1:7117
cargo run -- --port 8080       # другой порт
herdr-gpui browser open localhost:7117   # вкладка в herdr-gpui (на Linux-сборке без вкладок — системный браузер)
```

Один бинарник, страница встроена в него (`include_str!`), внешних ресурсов и CDN нет. Слушает только `127.0.0.1`.

- Порт: `--port N`, иначе `HERDR_PLANNER_PORT`, иначе `port = N` в `~/.config/herdr-planner/config.toml`, иначе `7117`.
- Папка данных доски (`repos.json`, `repo-keys.json`, `spaces.json`, `tasks/`): `--data DIR`, иначе `HERDR_PROJECTS_DATA_DIR`, иначе
  `data = "…"` в том же config.toml, иначе `~/.herdr-projects/data`. Если папка названа явно, она же передаётся командам доски
  (`HERDR_PROJECTS_DATA_DIR`); иначе доска находит свою сама. Старые `--root` / `HERDR_PROJECTS_ROOT` / `root = …` не читаются.
- Состояние (группы проектов, настройки): `~/.local/state/herdr-planner/state.json` (`$XDG_STATE_HOME`).
- `herdr-projects` ищется в `PATH`; `HERDR_PROJECTS_BIN=/путь` переопределяет. `HERDR_BIN=/путь` — `herdr` (активное пространство),
  `HERDR_SOCKET_PATH` — сокет сервера herdr (по умолчанию `~/.config/herdr/herdr.sock`; нужен для «показать все проекты»).

Постоянная установка (служба `systemd --user`, ярлык и горячая клавиша Omarchy) — раздел «Установка».

## Установка

Без `sudo` и системного пакетного менеджера; всё лежит в домашней папке. Нужны `cargo` (или `mise` с `rust@stable`),
`systemd --user`; для клавиши — Omarchy на Lua-конфиге Hyprland (`~/.config/hypr/bindings.lua`), `hyprctl` и `jq`.

```sh
scripts/install.sh              # собрать release, поставить, включить службу, ярлык, клавишу и значок в панели Omarchy
scripts/install.sh status       # что стоит, включена ли служба, отвечает ли порт
scripts/install.sh uninstall    # убрать всё установленное
```

Что и куда ставится:

| Что | Куда |
|---|---|
| бинарник и открывалка | `~/.local/bin/herdr-planner`, `~/.local/bin/herdr-planner-open` |
| служба | `~/.config/systemd/user/herdr-planner.service` (из `packaging/`, включена и запущена) |
| ярлык приложения | `~/.local/share/applications/herdr-planner.desktop`, значок `…/icons/hicolor/scalable/apps/herdr-planner.svg` |
| клавиша | `~/.config/hypr/herdr_planner.lua` и один помеченный блок в `~/.config/hypr/bindings.lua` |
| значок в панели | плагин оболочки `~/.config/omarchy/plugins/salehardec.herdr-planner/` (копия `packaging/omarchy-plugin/`) и один пункт в `bar.layout.center` файла `~/.config/omarchy/shell.json` сразу после часов |

**Обновление** — тот же `scripts/install.sh` после `git pull`: пересобирает, подменяет бинарник (через переименование, работающий
файл не затирается) и перезапускает службу. Группы и настройки (`~/.local/state/herdr-planner`, `~/.config/herdr-planner`)
не трогаются; `uninstall` их тоже оставляет. Флаги: `--no-build` (взять уже собранный `target/release/herdr-planner`),
`--no-service`, `--no-hypr`, `--no-shell`, `--key "SUPER + ALT + P"`. `HERDR_PLANNER_BIN_DIR` — другая папка для бинарников, `HERDR_PLANNER_SRC` — другой собранный бинарник.

**Служба.** `herdr-planner.service` слушает только `127.0.0.1:7117` (порт — `config.toml` или `HERDR_PLANNER_PORT`, см. «Запуск»),
перезапускается при сбое (`Restart=on-failure`, пауза 2 с), стартует вместе с пользовательской сессией systemd. Вывод — в journal:

```sh
systemctl --user status herdr-planner
journalctl --user -u herdr-planner -f
systemctl --user restart herdr-planner
```

В юнит записывается `PATH` с папками, где на момент установки нашлись `herdr-projects`, `herdr` и `claude`: у служб
systemd нет `PATH` оболочки. Если эти программы переехали, запусти установку ещё раз. Запущенный вручную `herdr-planner`
занимает порт — останови его (`pkill -x herdr-planner`), иначе служба не поднимется.

**Открытие** (`herdr-planner-open`, его вызывают ярлык и клавиша): запускает службу, если она стоит, затем

1. вкладка herdr-gpui — `herdr-gpui browser open localhost:7117`, но только если у запущенного herdr-gpui есть вкладки. На
   Linux-сборке их нет, и её `browser open` сам отправляет страницу в системный браузер (код 0), поэтому наличие вкладок
   сначала проверяется пробой, которая ничего не открывает: `herdr-gpui browser text 999999999` (чтение вкладки, которой
   быть не может). Код 8 — «эта сборка без вкладок», 3 — herdr-gpui не запущен: тогда вкладка пропускается. Любой другой
   (на сборке с вкладками — 5, «такой вкладки нет») — вкладки есть, и страница открывается вкладкой; как только Linux-сборка
   получит вкладки, это включится само, без правок;
2. иначе окно Omarchy (`omarchy-launch-or-focus-webapp`: уже открытое окно получает фокус, окно ищется по заголовку страницы,
   режим `chromium --app`, не вкладка обычного браузера);
3. иначе `xdg-open`.

Форсировать способ: `herdr-planner-open --tab | --window | --browser` или `HERDR_PLANNER_OPEN=tab|window|browser`;
`--tab` без вкладок завершается ошибкой и ничего не открывает. Проверка — `scripts/check-open.sh` (поддельные `herdr-gpui`,
лаунчер и `xdg-open`, входит в `scripts/run-checks.sh`).

**Клавиша Hyprland.** `scripts/install.sh` выбирает первую свободную из `SUPER + ALT + P`, `SUPER + SHIFT + H`,
`SUPER + SHIFT + L`, `SUPER + SHIFT + T`, `SUPER + SHIFT + Z`, сверяясь с `hyprctl binds`; своя — `--key "SUPER + …"` (занятая
отклоняется). Привязка лежит в отдельном файле `herdr_planner.lua`, в `bindings.lua` дописан только блок между
`-- >>> herdr-planner (scripts/install.sh) >>>` и `-- <<< herdr-planner <<<` с `pcall(require, …)` — ошибка в нашем файле не
ломает конфиг. Повторная установка блок не дублирует и выбранную клавишу сохраняет; `uninstall` вырезает только свой блок.
Проверить: `hyprctl binds | grep -B6 -A3 "Herdr Planner"` или `SUPER + K`.

**Значок в панели Omarchy** (`packaging/omarchy-plugin/`, плагин оболочки `salehardec.herdr-planner`, quickshell/QML). Пилюля в
стиле соседних чипов (SSH, Disk): `Plan`, затем `🔔 N` — задач доски, которые ждут тебя (см. ниже), и `👁 M` — задач на ревью у
ревьюера (нулевой счётчик не рисуется; пока ничего не ждёт, пилюля тихая — цвет обычного чипа, а не акцента). Подсказка при
наведении: `Herdr Planner · ждут тебя: N · к одобрению: R · упали: F · ревью: M · в работе: W`, под ней по строке на проект,
самый свежий первым: `alpha: ALP-2: ждёт ответа; ALP-4: готова к одобрению`. Числа — из `GET /api/summary`, опрос раз в 5 с
(`refreshSec`), без SSE; служба не отвечает — значок скрывается (опрос реже, раз в 10 с), в логе шелла ничего не пишется. Цвета —
из темы Omarchy (`Color.accent`, `Color.background`, цвет текста панели). Браузер значок не открывает.

**Клик по значку** — окошко оболочки под ним (`KeyboardPanel`, как у `salehardec.agents` и SSH-плагина; данные —
`GET /api/overview`, пока окошко открыто, обновляются раз в 5 с). В окошке нет «тихих» проектов — тех, где нет ни ждущих, ни
упавших, ни ревью, ни работающих, ни стоящих в очереди задач; остальное:

- сверху две кнопки: «Показать все проекты» (клавиши `U` / `0`) — просьба серверу herdr очистить представление агентов боковой
  панели (`agent.view.clear` через его сокет; у доски такой команды нет, а herdr не даёт узнать, отфильтрована ли панель, —
  поэтому пункт есть всегда) и «Полный планировщик» (клавиша `O`): запускает `herdr-planner-open` (вкладка herdr-gpui, если у неё
  есть вкладки, иначе окно приложения Omarchy — не системный браузер; подробности в разделе «Открытие»);
- три раздела, пустой не рисуется: «Ждут тебя» (`🔔`: ждёт ответа, план готов, выбор варианта, ревью не прошло, готова к
  одобрению, упала), «На ревью» (`👁`), «Работают» (`⚙`: в работе и в очереди). Проект стоит в первом подходящем разделе один раз.
  В первых двух свежие сверху: по времени, когда последняя из ждущих (в «На ревью» — последняя из ревью) пришла в свою стадию (`since`), справа от имени —
  «5 мин», «2 ч», «3 дн» назад;
- под именем проекта — его задачи по стадиям, что требует тебя первым (не больше пяти; сделанные и не начатые не рисуются):
  `ALP-4 Тёмная тема — готова к одобрению`, `ALP-6 Миграция базы — в работе 40%`; ниже полоска и `сделано/всего`;
- если все разделы пусты — строка «Всё тихо»; внизу всегда одна неактивная строка «ещё N проектов без активности»
  (без курсора и перехода);
- клик или `Enter` по проекту — полный планировщик на этом проекте: `POST /api/action {kind:"show", slug}` запоминает просьбу на 20 с
  (и шлёт событие `show`), затем запускается `herdr-planner-open`; открытая или только что открывшаяся страница показывает
  карточку проекта (один раз на просьбу); окошко закрывается, отказ приходит уведомлением Omarchy;
- клавиши: `↑ ↓` / `j k` — по строкам, `← →` / `h l` на заголовке раздела — свернуть и развернуть (до перезапуска шелла),
  `Enter` / пробел / клик — действие, `U` или `0` — показать все, `O` — полный планировщик, `R` — обновить, `Esc` — закрыть.

**Стадии доски** (`src/board.rs`, одно место для страницы, `/api/summary`, `/api/overview`, значка и окошка). Стадию задачи решает
доска, планировщик её только читает: поля `state`, `kind`, `stage`, `review` из `list --json`, правила — как у группировки самой доски
(`needs you`, `ready to approve`, `working`, `to do`, `done`), но с отдельными «упала», «на ревью» и «в очереди»:

| Стадия | Что это | Слова на странице | Команды |
|---|---|---|---|
| **ждёт тебя** | `blocked`: вопрос (`kind=question`), разрешение (`permission`), вход (`auth`), план (`stage=plan`), выбор из попыток (`stage=pick`), ревью не прошло (`stage=approval`, `review.pass=false`), остановка на лимите (`stage=stopped`), ревьюеру нужен ты (`stage=reviewneeds`), работа, которую доска не вольёт простым «да» (`stage=approval`, а в сообщении доски — проверки PR не прошли, слияние не вышло, отстаёт от main) | ждёт ответа · ждёт разрешения · нужен вход · план готов · выбери вариант · ревью не прошло · остановлена на лимите · ревьюеру нужен ты · нельзя влить | `tell` (ответить), `stop`; план — `approve`; ревью не прошло — `review`, `approve --anyway`; нельзя влить — `approve --anyway` (и `review`, если ревью было); остановка на лимите — `retry` (продолжить); выбор — на доске (`pick`) |
| **готова к одобрению** | `blocked` + `permission` + `stage=approval`, ревью прошло или его не было | готова к одобрению | `approve`, `approve --anyway`, `review` (если ревью было), `tell` |
| **упала** | `state=error`, `stage=failed` или `nosummary` (остановилась без итога) | упала · остановилась без итога | `retry`, `tell`, `stop` |
| **на ревью** | `working` + `stage=reviewing` | на ревью | `tell`, `stop` |
| **в работе** | `working`, в том числе шаги самой доски (`starting`, `setup`, `checking`, `pushing`, `merging`) | в работе · запускается · вливается … | `tell`, `stop` |
| **в очереди** | `working` + `stage=queued` (ждёт слот, `queue` — место) или `after` (ждёт другие задачи) | в очереди, №2 · ждёт другие задачи | `tell`, `stop` |
| **не начата** | остальное (`idle`), в том числе остановленная вручную (`stage=stopped`, `idle`) | не начата · остановлена | `delegate` |
| **сделана** | `state=done` | сделана | — |

В списке доски нет признаков упавших проверок PR, неудавшегося слияния и отставания от main (они во внутренних полях доски), поэтому «нельзя влить» определяется по словам сообщения доски, а у работы, которая выглядит готовой, рядом с «Одобрить» всегда есть «Одобрить всё равно». Архивные задачи не читаются (`list` без `--archived`), попытки задачи (`stage=tried`) остаются у своей задачи. Счётчик «ждут тебя»
(`🔔`, `waiting`) — задачи в стадиях «ждёт тебя», «готова к одобрению» и «упала»: то, где без тебя ничего не двинется. «На ревью» (`👁`) —
то, над чем работает ревьюер; пока он работает, от тебя ничего не нужно. Время «когда пришло» — `at` из `tasks/<репо>/<номер>/task.json`
в папке данных доски (читается только оно; нет файла — времени нет, остальное работает).

`install.sh` копирует плагин (не ссылку: ворктри может исчезнуть), вставляет `{"id": "salehardec.herdr-planner", "chip": false}`
после `bar.centerAnchor` (часы; иначе `omarchy.clock`, иначе в конец центра) и просит запущенный шелл пересканировать плагины;
свои правки пункта (например `"chip": "highlight"`) обновление не трогает, `port` пишется в пункт только если порт не 7117.
Перед правкой `shell.json` лежит копия `shell.json.bak-herdr-planner-<время>`; без `jq`, без раскладки панели в `shell.json` или с
`--no-shell` значок пропускается (вручную: `omarchy plugin enable salehardec.herdr-planner center`). `uninstall` убирает папку
плагина (только если в её `manifest.json` наш id) и свой пункт, остальной `shell.json` не меняется. Если QML правился, а
панель не обновилась, — `omarchy restart shell`. Проверка установщика — `scripts/check-install.sh` (временные папки, поддельный
`systemctl`, шелл не трогается).

## Архитектура

```
src/main.rs        запуск: состояние → тема → фоновые циклы → HTTP на 127.0.0.1:PORT
src/config.rs      порт, папка данных доски, XDG-пути, `herdr-projects` / `herdr` / сокет herdr
src/app.rs         общее состояние сервера: снимок проектов, сохранённое состояние, тема, активное пространство, шина событий, команды доски
src/board.rs       задачи доски: разбор `list --json`, стадия каждой (ждёт тебя / к одобрению / упала / на ревью / в работе / в очереди / не начата / сделана), слова для неё, команды, итог ревью
src/model.rs       чистая логика: проекты из задач, счётчики, сортировка, чипы, фильтр, группы, сопоставление пространства с проектом, итоги для значка и окошка
src/poller.rs      фоновые циклы: доска (20 с, или по запросу), активное пространство herdr (3 с), файлы темы (2 с)
src/actions.rs     команды доски для задачи (стадия проверяется, аргументы собираются здесь), подробности (`details`), «показать все проекты» (сокет herdr)
src/sources/       источники данных — чистые разборщики + неблокирующий запуск команд (tokio::process)
  repos.rs           папка данных доски: repos.json, repo-keys.json, spaces.json, tasks/<репо>/<n>/task.json (только чтение)
  runner.rs          запуск команды с таймаутом и окружением
  workspace.rs       `herdr workspace list` → активное пространство (id и метка)
src/store.rs       state.json: группы, настройки (таблица `SETTING_DEFS`); ключи прошлых версий проходят через сохранение как были
src/import_tern.rs перенос группы и настроек плагина из daemon.state Tern при первом запуске
src/theme.rs       тема herdr-gpui → CSS-переменные
src/agent.rs       слой «дешёвый агент» (Haiku / DeepSeek через omp): команды и запуск; им пользуется раскладка по группам
src/jsonscan.rs    JSON в ответе агента среди текста и ``` (разбор раскладки)
src/suggest.rs     автопредложение групп: запрос, разбор ответа (строки / объекты / обёртки), «Разложить заново»
packaging/omarchy-plugin/  плагин оболочки Omarchy: значок со счётчиками и окошко с проектами и задачами (manifest.json, Widget.qml)
src/api.rs         HTTP: страница, JSON API, SSE, защита от чужих сайтов (Host / Origin)
web/               страница: index.html, app.css, app.js (список), card.js (карточка проекта и панель задачи), settings.js (настройки и группы),
                   util.js (общее) — встраиваются в бинарник
scripts/ui-check.mjs    проверка страницы в headless Chromium
scripts/fixture.mjs     мир для проверок: папка данных доски с задачами во всех стадиях, поддельные herdr-projects / herdr / claude
scripts/run-checks.sh   всё вместе: cargo test + страница на фикстуре
```

Поток данных: `poller` раз в 20 с вызывает `herdr-projects list --json` и обычный `list` (его первая колонка — ключ задачи, `PLN-1`;
строки идут в том же порядке, и ключ принимается, только если его номер совпал с номером задачи), читает папку данных доски
(репозитории, ключи, время стадий), собирает проекты — репозитории доски, и те, у которых есть только задачи, — и кладёт снимок в
`App`, шлёт событие `snapshot`; страница держит один `EventSource` на `/api/events` и перерисовывается. Подробности задачи
(`details`) страница спрашивает только для выбранной. Никаких блокирующих вызовов в обработчиках HTTP: команды идут через
`tokio::process` с таймаутом, чтение файлов — в `spawn_blocking`. Не ответила доска или ответила не JSON — ошибка видна на странице
словами доски, прежний снимок остаётся.

### HTTP API

| Метод и путь | Что делает |
| --- | --- |
| `GET /` `/app.css` `/app.js` `/util.js` `/card.js` `/settings.js` | страница |
| `GET /api/snapshot` | проекты (`key`, `path`, `counts` по стадиям, `tasks`, `waits`, `attention_since`, `activity`, `done_hidden`), группы, настройки, активное пространство, `show`, версия |
| `GET /api/summary` | сводка для значка в панели: `{waiting, needs, ready, failed, waiting_hint, attention_since, review, working, queued, projects, updated, loading, error, version}` — `waiting` = ждёт тебя + к одобрению + упала, по строке на проект в `waiting_hint` (свежие первыми), время самого свежего события в мс; маленький ответ вместо всего снимка |
| `GET /api/overview` | список для окошка в панели: `{summary, waiting, review, working, quiet}` — проекты по разделам (`waiting` и `review` — по `attention_since`, свежие первыми; проект в одном разделе) и число «тихих» проектов; у проекта `waiting, ready, failed, review, working (с очередью), done, total, wait_hint, attention_since, since, tasks` (`since` — время для окошка: у ждущего проекта `attention_since`, у проекта на ревью — когда началось его последнее ревью; до пяти строк `{id, tag, title, bucket, label, progress}`) |
| `GET /api/theme` | тема (см. ниже) |
| `GET /api/events` | SSE: `theme` и `snapshot` сразу, затем `snapshot` / `theme` / `workspace` / `show` (`{slug, at}`) |
| `POST /api/refresh` | обновить доску сейчас |
| `POST /api/groups` | `{op:"assign", slug, name}` · `{op:"add", name}` · `{op:"fold", name, folded?}` · `{op:"toggle", on?}` · `{op:"rename", name, to}` · `{op:"move", name, delta}` · `{op:"delete", name, to?}` · `{op:"resort"}` |
| `POST /api/settings` | `{key, value}` — одна настройка (значение проверяется по `SETTING_DEFS`); снимок и событие `snapshot` приходят следом |
| `POST /api/action` | `{kind:"unfocus"}` → `agent.view.clear` через сокет herdr (боковая панель снова показывает все проекты); `{kind:"show", slug}` → страница откроет карточку проекта (404, если его нет на доске). Других действий нет (`focus` / `open` исчезли вместе со старым herdr-projects) |
| `GET /api/task?id=` | подробности задачи из `herdr-projects details <id> --json`: стадия, сообщение, сбой, ревью с замечаниями, план, ветка, PR, ворктри, лимиты, команды стадии (400 — id не похож на задачу, 404 — доска такой не показывает) |
| `POST /api/task/action` | `{id, kind, text?}`, `kind` — `approve` · `anyway` (`approve --anyway`) · `review` · `retry` · `delegate` · `stop` · `tell`: команда доски для задачи. Сервер берёт задачу из своего снимка и пропускает команду, только если она есть в списке команд её стадии (409 иначе); `tell` шлёт текст после `--`, `anyway` — только там, где он есть в списке команд стадии; ответ доски — в `message`, отказ доски — 502 с её словами |

### Фронтенд: почему без фреймворка

Состояние страницы маленькое (фильтр, чип, сортировка, подсветка, открытый проект, у карточки — вкладка, фильтр, выбранная
строка и открытая задача, у настроек — строка и правка группы), вид — список, карточка и экран настроек поверх них. Поэтому
страница — обычные ES-модули с JSDoc-типами (`// @ts-check`; `npx -p typescript tsc --noEmit --allowJs --checkJs --target es2022
--module es2022 --moduleResolution bundler --lib es2022,dom,dom.iterable web/*.js` проверяет типы), без сборки: `cargo build` —
единственный шаг, страница встраивается как есть. Карточка — отдельный модуль `card.js`, настройки — `settings.js`, у каждого своё
состояние, но экран по-прежнему один без независимых виджетов, поэтому сборщик и фреймворк по-прежнему не нужны. Весь экран
перерисовывается целиком; поля ввода, каретка и прокрутка списка переживают перерисовку (`render()` в `app.js`).

Горячие клавиши не зависят от раскладки: буква берётся по физической клавише (`ч` на клавише X — это `x`),
в полях ввода клавиши остаются как набраны.

Логика списка (сортировка, чипы, фильтр, группы) есть и в `src/model.rs` (эталон, покрыт тестами; группы — и
работа сервера: правка, перенос при удалении, автопредложение), и в `app.js` (чтобы фильтр и подсветка не ходили на сервер).
Менять — в обоих местах.

## Откуда тема

herdr-gpui не хранит файлы тем: встроенные (Default, Nord, Dracula, Catppuccin Mocha, Catppuccin Latte) — палитры
в его исходниках (`crates/herdr-gpui/src/config/theme.rs`), и `src/theme.rs` несёт те же значения. Что выбрано,
читается из конфигов `~/.config/herdr/`: `config-gpui.local.toml` (выбор пользователя) поверх `config-gpui.toml`
(умолчания), таблицы сливаются по ключам, как в herdr-gpui:

- `theme = "Nord"` — встроенная тема;
- `theme = "Follow Herdr"` — тема демона herdr из `~/.config/herdr/config.toml` (`[theme] name`, `auto_switch`,
  `light_name`/`dark_name`, `[theme.custom]` с переопределениями `panel_bg`, `accent`, …): палитры UI herdr
  (`herdr_settings/palette.rs`) перенесены в `theme.rs`;
- имя темы Ghostty — файл ищется в `~/.config/herdr/themes`, `~/.config/ghostty/themes`, `$GHOSTTY_RESOURCES_DIR/themes`,
  `~/.local/share/ghostty/themes`, `/usr/share/ghostty/themes` (формат Ghostty: `background`, `foreground`,
  `cursor-color`, `palette = N=#rrggbb`); `~/путь` и абсолютный путь — тоже;
- `theme = "light:A,dark:B"` — обе стороны отдаются странице, она выбирает по `prefers-color-scheme` и следит за сменой.

Производные цвета считаются как в GUI: `surface`/`active`/`muted` — смешение фона и текста (5 / 12 / 55 %),
акцент — `palette[5]`, `accent-wash` — 22 % акцента на поверхности, `contrast = "high"` сдвигает `active`.
Шрифты — `[ui]` и `[terminal]` тех же файлов (`family`, `size`); установленные шрифты не проверяются, в CSS
стоит запасной стек. Файлы темы опрашиваются по mtime каждые 2 с, изменение шлёт событие `theme` — смена
темы в herdr-gpui подхватывается без перезапуска. Если тему прочитать нельзя, показывается палитра Default и
в `/api/theme` поле `error` говорит почему.

CSS-переменные страницы: `--bg --fg --surface --active --muted --subtext --accent --accent-wash --border --sidebar
--cursor --black … --white --bright-*`, `--font-ui --font-mono --size-ui`.

## Список проектов

Паритет с плагином 0.17.1 (см. его README, раздел «Список проектов»), но данные — задачи доски:

- Заголовок «Планировщик проектов · N проектов · vX.Y.Z», «⚙ Настройки» (`,`), «обновлено … ↻» (клик — обновить). Под ним строка
  счётчиков по всем задачам доски: «6 ждут тебя · 2 к одобрению · 2 упали · 3 на ревью · 2 в работе · 2 в очереди» (нулевые не пишутся;
  «на доске всё тихо», если ничего нет).
- Строка управления: фильтр (`/`, ищет по имени, slug и ключу), чипы Все / Ждут / В работе / Тихие с числами (`1`–`4`; «Ждут» —
  есть ждущая, готовая к одобрению или упавшая задача, «В работе» — есть работающая, на ревью или в очереди, «Тихие» — ничего из
  этого), «⇅ новые / внимание» (`s`), «▦ группы вкл / выкл» (`g`), «◎ все проекты» (`u`).
- Строки: иконка (🔔 ждёт тебя или одобрение, ✖ упала, ◉ работа или ревью, ◌ очередь, ○ тихий проект), имя, ключ (`ALP`), «авто» у
  группы от агента; справа «N ждут», «N к одобр.», «N упала», «N ревью», «N в работе», «N в очереди», как давно пришла ждущая задача
  («5 мин», «2 ч»), «сделано/всего» (по задачам доски). Вторая строка — что именно ждёт («ALP-2: ждёт ответа; ALP-4: готова к одобрению»),
  иначе первая работающая задача с процентом. Тихие проекты — приглушённо.
- `↑` / `↓` подсвечивают (заголовки групп тоже), у подсвеченной строки справа её клавиши; одиночный клик подсвечивает,
  двойной открывает; `enter` открывает проект или сворачивает группу; `←` / `→` сворачивают / разворачивают группу;
  `u` — «показать все проекты» (боковая панель herdr снова показывает все проекты; то же — переключатель «◎ все проекты»),
  `r` — обновить, `?` — все клавиши, `esc` — сбросить фильтр и чип, затем подсветку; из открытого проекта `esc` возвращает в
  список с подсвеченным проектом.
- Фильтр: `↑` / `↓` выходят из поля и двигают подсветку, текст остаётся; `enter` открывает первый найденный.
- Группы: заголовок `▾` / `▸`, имя, число, сводка (ждут / ревью / в работе); свёрнутая показывает имена проектов приглушённо;
  «Прочее» в конце; при фильтре пустые группы скрыты. `t` на проекте — выбор группы (группы, «новая группа…», «без группы»),
  ручной выбор не перезаписывается автоматикой. Всё хранится в state.json.
- Сортировка «новые» — по времени последнего перехода любой задачи проекта в новую стадию; «внимание» — кто ждёт тебя, свежее событие
  выше (время рядом с «N ждут»), затем ревью и работа.
- Новых проектов из страницы не создать: у доски нет такой команды (репозиторий появляется на доске, когда в нём заводят задачу).

## Карточка проекта

`enter` на проекте, клик по проекту в окошке панели или смена пространства herdr открывает карточку. Задачи берутся из снимка, отдельных
запросов список не делает.

- Шапка: «← Назад», имя и ключ проекта, «⚙» (настройки, `,`), «Все U», «обновлено … ↻». Под ней «Папка» (путь репозитория доски) и шкала
  «N из M сделано» со счётчиками стадий проекта.
- Вкладки «В деле / Сделано» (`tab`, `1` / `2`), фильтр `/` (находит по ключу, id, названию, стадии, сообщению, агенту, PR; `↑` / `↓`
  выходят из поля, текст остаётся). В «В деле» задачи идут разделами в порядке стадий — «Ждут тебя», «Готовы к одобрению», «Упали», «На
  ревью», «В работе», «В очереди», «Не начаты» (внутри раздела свежие выше); в «Сделано» — последние 40 сделанных (остальные только
  посчитаны, их видно на доске).
- Строка задачи: значок стадии, ключ (`ALP-6`), название; справа стадия словами, у работающих и на ревью процент и «ещё N мин», у задач
  с ревью `R#N` (красным — не прошло, синим — идёт, серым — сделана), `PR#N` и как давно; под ней сообщение доски (то, что задача
  говорит сейчас, или итог ревью: `Review failed · 1 critical, 1 major`).
- **Панель задачи.** Клик или `enter` на строке открывает панель под списком (ещё раз — закрывает; `esc` закрывает): стадия, сообщение,
  агент, ветка, ворктри, PR (ссылка), место в очереди, время работы агента — из `herdr-projects details`; сбой (заголовок, текст,
  что делать дальше — текст остаётся текстом, разметка не исполняется); ревью: прошло / не прошло, итог (`1 critical, 1 major`),
  круги и замечания с серьёзностью, местом и доказательством (до восьми, найденные до задачи не считаются); план, если он ждёт
  одобрения; для «выбери вариант» — подсказка `herdr-projects pick <id> <буква>` (выбор делается на доске).
- **Команды доски** для стадии выбранной задачи (кнопки и клавиши; других сервер не пропустит):

  | Стадия | Кнопки |
  |---|---|
  | ждёт ответа / разрешения / входа | «Ответить» (`m`, поле → `herdr-projects tell <id> -- текст`), «Остановить» (`x`, `stop`) |
  | план готов | «Принять план» (`a`, `approve`, с подтверждением), «Ответить» (`m`: отправить план обратно со словами) |
  | ревью не прошло | «Отправить ревью агенту» (`v`, `review`), «Одобрить всё равно» (`w`, `approve --anyway`, с подтверждением), «Ответить» |
  | нельзя влить (проверки PR, слияние, отставание от main) | «Одобрить всё равно» (`w`), «Отправить ревью агенту» (`v`, если ревью было), «Ответить» |
  | готова к одобрению | «Одобрить» (`a`, `approve`, с подтверждением), «Одобрить всё равно» (`w`, если доска не вольёт простым «да»), «Отправить ревью агенту» (`v`, если ревью было), «Ответить» |
  | остановлена на лимите | «Повторить» (`e`, `retry`: работа продолжится), «Ответить» |
  | упала | «Повторить» (`e`, `retry`), «Ответить», «Остановить» |
  | на ревью, в работе, в очереди | «Ответить», «Остановить» |
  | не начата, остановлена вручную | «Запустить» (`d`, `delegate`) |
  | выбери вариант, сделана | команд нет |

  Одобрение спрашивает «Одобрить и влить работу? [Да y] [Нет n]» (для плана — «Принять план? Агент начнёт работу.», для не прошедшего
  ревью — «Ревью не прошло. Влить всё равно?», для «нельзя влить» — объяснение, почему доска просит «всё равно»): это слияние или старт работы. Остальные команды выполняются сразу. Ответ доски
  показывается в строке состояния («ALP-4: одобрить — ALP-4: approved»), отказ доски — её словами; после команды снимок обновляется сразу,
  и задача сама переходит в новую стадию. Панель следует за задачей, пока она остаётся на своей вкладке; ушла в «Сделано» — закрывается.
- Клавиши: `/` · `tab` / `1` / `2` · `↑` `↓` · `enter` · `u` · `r` · `,` настройки · `esc` (закрыть панель, затем назад); при открытой
  задаче — `a` `w` `v` `e` `d` `x` `m` (только те, что есть у её стадии).

## Настройки

«⚙ Настройки» в списке, «⚙» в карточке, клавиша `,`; `esc` или «← Назад» закрывают. Экран строится из таблицы
`SETTING_DEFS` в `src/store.rs` (ключ, подпись, подсказка, варианты, умолчание) — новая настройка это ещё одна запись;
неизвестное или испорченное значение возвращается к умолчанию.

| Настройка | Варианты | Умолчание |
| --- | --- | --- |
| Дешёвый агент | Claude Haiku 5.5 · DeepSeek Flash (omp) | Claude Haiku 5.5 |
| Автопредложение групп | вкл · выкл | вкл |

Настройки старой схемы («Автопроверка актуальности» задач `TASKS.md`, «Забытое ревью» тредов) убраны вместе с тем, чему они служили. Их значения
в `state.json` остаются как были (см. «Сохранённое состояние»).

Клавиши: `↑` / `↓` строка · `←` / `→` / `enter` значение · на группе `[` / `]` (или `shift`+`↑`/`↓`) порядок, `enter`
переименовать, `x` удалить (затем `y` / `n`; у группы с проектами `←` / `→` выбирают, куда их перенести) · `a` добавить
группу · `esc` назад. Всё то же — кнопками.

Под настройками карточка «Группы проектов»: порядок групп (↑ ↓), переименование (проекты и «свёрнутость» идут за именем),
удаление, «+ Группа» и «↻ Разложить заново». Удаление пустой группы — «Да» / «Нет»; у группы с проектами: «В группе N проектов.
Перенести в: [Прочее ▾]»: в другую группу проекты переходят ручным выбором, в «Прочее» — как были (ручной выбор остаётся
ручным, «авто» остаётся догадкой). «Разложить заново» стирает только «авто»-назначения и просит агента ещё раз, даже при
выключенном автопредложении. Название «Прочее» занято.

## Автопредложение групп

Проекту без группы дешёвый агент подбирает группу по имени, папке репозитория и названиям его четырёх новейших задач. Один вызов на все
проекты без записи, один раз на проект (новый репозиторий доски получает группу при появлении в списке — сервер проверяет это после
каждого чтения доски); ответ — JSON `[{"slug":"…","group":"…"}]`, разбор терпит ``` и текст вокруг, объект «slug → группа»,
«группа → [slug]» и обёртки; мусор группой не становится (ошибка — тихая строка в настройках, повтор не раньше чем через
5 минут). Агент выбирает из списка групп и называет новую (не больше трёх за раз) только если проект явно ни к одной не
подходит. Автоназначение помечено в строке «авто»; ручной выбор не перезаписывается. Стартовый набор: Omarchy · ЯНАО ·
ИИ-инфраструктура · Агенты и herdr · Личное. Репозитории не меняются; агент только читает.

## Следование за пространством herdr

Сервер раз в 3 с спрашивает `herdr workspace list` и берёт пространство с `"focused": true` (id и метка; хвостовой U+2800
убирается). Проект ищется в таком порядке:

1. ключ задачи в начале метки (`PLN-1 Заголовок` — так называется пространство задачи на доске): проект с ключом `PLN`;
2. пространство, которое доска открыла для репозитория (`spaces.json` в папке данных: папка → id пространства): проект с такой папкой;
3. имя проекта или slug без учёта регистра; два проекта с одним именем — не сопоставляются.

Страница реагирует только на смену (`seq` в событии `workspace`): открывает карточку проекта; уход в список (`esc`) держится до
следующей смены; пока идёт ввод (фильтр, выбор группы), переключение ждёт и применяется, когда поле закрыто.

## Сохранённое состояние

`~/.local/state/herdr-planner/state.json` держит группы проектов (список, назначения с пометкой «авто», свёрнутые, переключатель) и
настройки. Группы ключуются именем репозитория — оно совпадает со slug прежних проектов, поэтому группы пережили переход на доску
без правок. Ключи, которых планировщик больше не знает (`qa`, `sent`, `fresh`, `last_dir` и устаревшие настройки), не удаляются:
они проходят через каждое сохранение как были (`State::legacy`, `Settings::other`) — на случай возврата к прежней версии.

При первом запуске (нет state.json) `import_tern.rs` только читает `~/.local/state/tern/daemon.state` (бинарный файл Tern рядом со
строкой `herdr-dashboard.dashboard`), находит последний JSON-объект с ключами плагина и переносит группы (список, назначения,
свёрнутые, переключатель) и настройки; ответы на вопросы по задачам, отметки «отправлено» и вердикты актуальности (то, что относилось к
`TASKS.md`) не переносятся. Источник записывается в `imported_from`. Файл Tern не меняется.

## Тесты

```sh
cargo test                       # разбор доски и стадии задач, проекты и счётчики, сортировка/фильтр/группы (правка, перенос,
                                 # удаление), итоги для значка и окошка, сопоставление пространства, файлы доски, команды для задач
                                 # (стадия, `--anyway`, `tell` после `--`), подробности, сокет herdr, тема, импорт, state.json
                                 # (в том числе: старый файл с `qa` / `fresh` сохраняется целиком), разбор ответа с группами
scripts/run-checks.sh [папка-для-скриншотов]   # то же + установщик во временных папках и с поддельным systemctl (scripts/check-install.sh;
                                 # настоящую службу пользователя и настоящий shell.json не трогает)
                                 # + страница на фикстуре (нужны node ≥ 22 и chromium)
cargo run &                      # или по отдельности, на живом сервере:
node scripts/ui-check.mjs http://127.0.0.1:7117 [папка-для-скриншотов]
```

`ui-check.mjs` без зависимостей (Node ≥ 22) открывает страницу в headless Chromium по DevTools-протоколу и проверяет:
строки списка, заголовок, отсутствие горизонтальной прокрутки, применение темы и шрифта, сводку для значка, клавиши `↑` `t` `esc` `s`
`/`, фильтр, открытие карточки и возврат. На живом сервере карточка и экран настроек проверяются только на чтение. С `FIXTURE=DIR`
(`run-checks.sh` делает всё сам) всё проверяется целиком на мире из `scripts/fixture.mjs` — папка данных доски (`--data`) с одиннадцатью
проектами, задачи во всех стадиях (вопрос, план, ревью прошло и не прошло, выбор, упала, остановилась без итога, на ревью, в работе, очередь,
`after`, не начата, сделана), и поддельные `herdr-projects`, `herdr`, `claude`, которые только пишут в `DIR/log/*.jsonl`, что у них
просили, и меняют `DIR/state/board.json`, как сделала бы доска: счётчики и порядок проектов, окошко панели (`/api/overview`), строки
списка, чипы, фильтр по ключу, «показать все проекты» (запрос к поддельному сокету herdr), карточка (разделы по стадиям, панель
задачи, подтверждение одобрения, `approve` / `approve --anyway` / `review` / `retry` / `delegate` / `stop` / `tell` с точными
аргументами, отказ доски, неверные входы API 400 / 404 / 409), следование за пространством (по `spaces.json`, по ключу в метке, по имени) и
просьба «показать» из окошка, доска, которая не отвечает или отвечает не JSON, настройки (агент, значения клавишами, добавление /
переименование / порядок / удаление групп, перенос проектов при удалении, «Разложить заново» и ручной выбор, неверные входы),
автопредложение для нового репозитория. Настоящая доска, агенты и боковая панель в проверках не участвуют. CI нет.

## История

- **Этап 1**: каркас, тема, список проектов, группы, следование за активным пространством herdr, перенос сохранённого состояния плагина.
- **Этап 2**: карточка проекта (треды с git-строками, задачи `TASKS.md`).
- **Этап 3**: настройки, автопроверка актуальности задач, автопредложение групп, форма «Новый проект».
- **Этап 4**: упаковка — `scripts/install.sh` (сборка release, установка и удаление, идемпотентно), служба `systemd --user`
  (`packaging/herdr-planner.service`), ярлык и значок (`packaging/`), `herdr-planner-open` (вкладка herdr-gpui → окно Omarchy →
  браузер), клавиша Hyprland, значок и окошко в панели Omarchy. Завершение по SIGTERM — не дольше 2 с.
- **Этап 5 (этот): переход на доску herdr-projects.** Старый herdr-projects (проекты с `PROJECT.md`, `TASKS.md`, треды, координаторы)
  заменила доска с задачами, стадиями, агентами, ревью и одобрением, поэтому источник данных стал доской: проекты — её репозитории,
  счётчики, прогресс и окошко панели считаются по задачам доски, у задачи есть панель с подробностями и команды доски. Убрано:
  чтение `TASKS.md` и «Решить» / «Не решать» / «Задать вопрос», автопроверка актуальности, вердикты агента по бэклогу, git-строки и
  бейджи моделей тредов, форма «Новый проект», `focus` / `open` проекта, догадки о вопросе координатора (дешёвый агент, транскрипты
  Claude), состояние MR GitLab (`glab`), «забыто» и «можно закрыть», настройки «Автопроверка актуальности» и «Забытое ревью».
  «Тихие проекты», «показать все проекты» и «Полный планировщик» остались. Группы и настройки пользователя сохраняются.
