# Herdr Planner

Отдельный дашборд доски **herdr-projects**: проекты, задачи, статусы, консоль
Координатора, журнал, «Ждёт тебя» и детали выбранной задачи. Работает сам по
себе — herdr (TUI) и herdr-gpui не нужны. Данные и команды идут напрямую в
`herdr-projects`.

Макет, по которому сделан интерфейс: [`design/herdr-planner.html`](design/herdr-planner.html)
и [`design/README.md`](design/README.md). Снимки макета — в [`design/screenshots/`](design/screenshots).

```

├─────────────────────────┬─────────────────────────┬───────────────────┤
```

## Установка

Нужны:

- Rust (сборка; если `cargo` стоит через mise, `scripts/install.sh` сам вызовет
  `mise x rust@stable -- cargo`);
- `herdr-projects` в `PATH` (доска);
- для значка в панели — Omarchy, `jq`, `systemctl --user`;
- для файлов — `yazi` и `xdg-terminal-exec`;
- для проверок — Node 22+ и Chromium.

Скрипт собирает **вне репозитория** — это важно, если репозиторий на NTFS, где
собранные файлы не запускаются:

```
~/.cache/herdr-planner/target
```

```sh
git clone <repo> herdr-planner
cd herdr-planner
scripts/install.sh
```

`scripts/install.sh`:

- собирает release в `${XDG_CACHE_HOME:-~/.cache}/herdr-planner/target`
  (переопределяется `HERDR_PLANNER_TARGET_DIR`);
- ставит `~/.local/bin/herdr-planner` и `herdr-planner-open`;
- включает `systemd --user` службу `herdr-planner.service`;
- ставит `.desktop`, значок, ярлык Hyprland и значок в панели Omarchy
  (`salehardec.herdr-planner` в `~/.config/omarchy/shell.json`);
- не трогает настройки, если их нет: без пароля служба слушает только
  `127.0.0.1:7117`.

Обновление — тот же `scripts/install.sh` (пересоберёт и перезапустит).
Удаление:

```sh
scripts/install.sh uninstall          # снимает службу, ярлыки и значок
scripts/install.sh status             # что установлено, слушает ли служба
```

Состояние (`~/.local/state/herdr-planner`: журнал, последнее сообщение чата)
и `~/.config/herdr-planner/config.toml` при удалении сохраняются.

### Значок и окно

Значок в панели Omarchy открывает **отдельное окно-приложение** (Chromium app
window, 1280×940), а не вкладку браузера. То же самое делает ярлык
«Herdr Planner» и `herdr-planner-open`. Служба стартует, если была остановлена.

## Доступ с другой машины: логин и пароль

По умолчанию сервис слушает `127.0.0.1` и не требует входа. Чтобы открыть его с
другой машины:

```sh
scripts/install.sh password --listen 0.0.0.0 --user me
```

Команда спрашивает пароль дважды, считает **Argon2id-хеш** (готовый bcrypt-хеш тоже принимается через `set-auth`) и пишет в
`~/.config/herdr-planner/config.toml` только хеш (файл с правами `600`):

```toml
listen = "0.0.0.0"
user = "me"
password_hash = "$argon2id$v=19$m=19456,t=2,p=1$…"
port = 7117
```

- Адрес настраивается (`listen`), порт — `port` (по умолчанию 7117).
  `0.0.0.0` слушает все интерфейсы, можно назвать и конкретный
  (например `192.0.2.5`). Локальное окно при этом откроется по этому
  адресу и будет вести себя как удалённый клиент (файлы — только путём);
  для полного локального режима оставьте `0.0.0.0` или `127.0.0.1`.
- **Всё API за входом.** Без сессии `/api/*` отвечает `401`; `/` перенаправляет
  на `/login`. Публичны только страница входа и её css/js/иконка.
- **Локальное окно тоже входит.** Мы не отключаем вход для `127.0.0.1`: этот
  адрес доступен любому процессу на машине, поэтому правило одно для всех.
  Значок Omarchy откроет ту же форму входа; Chromium в окне-приложении
  принимает `Secure`-cookie на loopback, так что вход запоминается на 30 дней
  (но сессии живут в памяти службы — после её перезапуска нужно войти снова).
  Если пароль не задан, служба и так слушает только loopback и входа нет.
- Сессия — случайный токен в cookie `HttpOnly; Secure; SameSite=Strict;
  Path=/`; на сервере живёт 30 дней.
- После 5 неудачных попыток за 5 минут адрес блокируется на 5 минут (`429`).
- `<`/`>` и прочие данные экранируются; CSP запрещает внешние скрипты и стили.

### HTTPS

Cookie помечена `Secure`, поэтому удалённый браузер не сохранит её на
`http://<ip>`. Для прямого доступа по IP включите TLS:

```sh
scripts/install.sh tls --cert /path/fullchain.pem --key /path/privkey.pem
```

Сертификат и ключ можно указать и в конфиге (`tls_cert`, `tls_key`). После
этого открывайте `https://<ip>:7117`. Если сертификата нет, поставьте перед
сервисом TLS-прокси (nginx/Caddy) или **Tailscale Serve** — тогда наружу
открывается только HTTPS, а сервис продолжает слушать `127.0.0.1`. Прокси
должен передавать `X-Forwarded-For` (Caddy делает это по умолчанию; в nginx
добавьте `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`):
по нему считаются неудачные входы и видно, что клиент удалённый, поэтому
yazi не открывается на сервере, а показывается путь.

`0.0.0.0` без TLS и без прокси сервис не запрещает, но предупреждает в логе.
Страница входа на удалённом адресе по HTTP тоже не отправляет пароль: она
показывает, что нужен HTTPS (cookie `Secure` всё равно не сохранилась бы).

### SSH-туннель (необязательно)

Туннель больше не нужен, но остаётся рабочим вариантом для отладки:

```sh
ssh -L 7117:127.0.0.1:7117 user@host
# затем http://localhost:7117 на своей машине
```

`localhost` (в отличие от `127.0.0.1`) страница считает удалённым клиентом:
кнопки файлов показывают путь, а не пытаются открыть yazi на сервере.

В этом режиме сервис на той стороне может оставаться на `127.0.0.1` без пароля.
Действия с файлами (yazi) всё равно выполняются только на машине с доской —
удалённая страница показывает путь.

## Координатор

Консоль в центре отправляет текст в:

```sh
herdr-projects coordinator tell "<текст>"
```

Показывается последний ответ. У доски **нет команды «прочитать последний
ответ»**: `herdr-projects coordinator` печатает строку состояния и последние
строки окна Координатора (через sidebar herdr). Именно этот хвост и показан,
с подписью «последнее из окна Координатора»; если herdr не запущен и хвоста
нет, страница честно пишет, что ответа пока нет. Это единственное место, где
интерфейс зависит от работающего herdr, и оно не влияет на задачи и действия.

Чат не копит историю: показан последний обмен (ваше сообщение и хвост ответа).
Черновик не теряется при обновлении данных. `Enter` — отправить,
`Shift+Enter` — новая строка, `Esc` — очистить.

## Задачи и действия

Данные:

- `herdr-projects list --all --json` — задачи и архив (`archivedAt`);
- `herdr-projects list --all` — короткие ключи (`PLN-3`);
- `herdr-projects details <id>` — по запросу: вердикт, проверки, ветка,
  worktree, `after`, лимиты;
- `herdr-projects show --task <id>` — модель агента (`worker.agent`).

Опрос — раз в 4 секунды; страница тоже обновляется раз в 4 секунды и сохраняет
выбранную карточку, фильтры и черновик. Смена темы Omarchy подхватывается без
перезагрузки.

| Статус | Что значит | Действия на карточке / в «Фокусе» |
|---|---|---|
| `waiting` | вопрос, разрешение, вход, остановка на лимите | Ответить (`tell`), Остановить |
| `failed` | ошибка или остановка без итога | Повторить (`retry`), Остановить |
| `ready` | готово к одобрению | Одобрить (2 клика) (`approve`), Всё равно (`approve --anyway`), Ревью |
| `plan` | план готов | Одобрить план (2 клика) |
| `review` | на ревью | — |
| `working` | в работе | — |
| `queued` | очередь / `after` / не начата | Запустить сейчас (`delegate --now`) |
| `done` | сделано | В архив (`archive`) |

**Одобрение всегда требует подтверждения**: первый клик взводит кнопку
(«Подтвердить одобрить» / «Подтвердить одобрить план»), второй — отправляет
команду. Подтверждение своё у каждой задачи и каждого действия: взведённое
«Одобрить» нельзя подтвердить кнопкой «Всё равно влить», и наоборот. Двойной
клик не считается подтверждением: второй клик игнорируется, если он пришёл
раньше, чем кнопка успела показать новую подпись. Сервер тоже отказывает
`approve`/`anyway` без `confirm: true` — это не только оформление.

Остальные действия: «Написать агенту» (`herdr-projects tell <id> <text>`),
«Вернуть ревью агенту» (`review`), «Остановить» (`stop`). Кнопки, которых нет
без herdr (вкладка агента, переход в пространство), помечены и объяснены; сам
планировщик их не подменяет.

### Архив

- На карточке «сделано» и в строке «Сделано ещё N» — значок «в архив».
- В заголовке проекта — «убрать все сделанные» этого проекта.
- В шапке — «Убрать сделанные» для всей доски.
- Кнопка «Архив» в шапке открывает список (`list --archived` по смыслу,
  сервер берёт архивные строки из `list --all --json`); «Вернуть» вызывает
  `herdr-projects restore <id>`.

Всё это — `herdr-projects archive <id>` / `restore <id>`; своих данных
планировщик не заводит.

### Файлы: yazi

Кнопка папки на карточке открывает worktree задачи в **yazi** отдельным окном
терминала (`xdg-terminal-exec yazi <папка>`). В «Фокусе» есть ещё «Отчёты и
заметки» (`~/.herdr-projects/reports/<repo>/<номер>`). У задачи в очереди
worktree ещё нет — кнопки нет. На удалённой странице кнопка показывает путь и
поясняет, что файлы открываются только на машине с доской. Своего просмотрщика
у планировщика нет.

## Статусы и тема

Цвета берутся из текущей темы Omarchy:

```
~/.local/state/omarchy/current/theme/colors.toml
~/.local/state/omarchy/current/theme.name
```

Сервис отдаёт странице «сырые» цвета (`--c-bg`, `--c-fg`, `--c-accent`,
`--c-yellow`, `--c-red`, …), остальные токены считаются в CSS через
`color-mix`. Поэтому на MacBook через браузер видны те же цвета, что и локально.
Тема перечитывается при каждом опросе (4 с) без перезагрузки; нити и анимации
подхватывают новые переменные сами.

Статус различим не только цветом: у каждого свой значок, подпись и положение
жетона на рейке этапов — это важно для монохромных тем (White). Анимации:
нити от Координатора к проектам и карточкам, бегущие огоньки по статусу,
«дыхание» задач в работе, появление/уход карточек, кольцо смены статуса.
`prefers-reduced-motion: reduce` и `?calm` отключают движение, не теряя смысл.

## Конфигурация

`~/.config/herdr-planner/config.toml` (все ключи необязательны):

```toml
listen = "127.0.0.1"          # адрес; 0.0.0.0 — для другой машины (нужен пароль)
port = 7117
data = "~/.herdr-projects/data"
user = "me"
password_hash = "$argon2id$…" # только хеш; задаётся scripts/install.sh password
tls_cert = "/path/fullchain.pem"
tls_key  = "/path/privkey.pem"
```

Приоритет: аргументы `--listen/--port/--data`, затем переменные
`HERDR_PLANNER_LISTEN`, `HERDR_PLANNER_PORT`, `HERDR_PROJECTS_DATA_DIR`, затем
конфиг. `HERDR_PROJECTS_BIN` задаёт путь к `herdr-projects`.

Служебные команды бинарника:

```sh
herdr-planner hash-password < password.txt   # Argon2id-хеш
herdr-planner set-auth --user me --listen 0.0.0.0 < hash.txt
herdr-planner set-tls --cert fullchain.pem --key privkey.pem
```

## Проверки

```sh
scripts/run-checks.sh [каталог-для-снимков]
```

Запускает:

1. `cargo test` — разбор `list --all --json`, восемь статусов, проекты и
   итоги, `details`, `show --agent`, журнал, тема, Argon2/bcrypt, лимит входов,
   cookie, X-Forwarded-For, абсолютные пути TLS.
2. `scripts/check-install.sh` — установка/удаление в временном HOME, права
   `600` у конфига, хеш вместо пароля, Hyprland/Omarchy, служба (через
   заглушку `systemctl`).
3. `scripts/check-open.sh` — окно-приложение по умолчанию, браузер только по
   `--browser`, HTTPS/порт/адрес из конфига (`0.0.0.0`, конкретный интерфейс,
   IPv6).
4. `scripts/ui-check.mjs` — headless Chromium на `scripts/fixture.mjs`: все
   статусы, счётчики, фильтры, approve и anyway только после видимого
   подтверждения (двойной клик не проходит), retry/tell с `--`, нити не
   выходят за колонку, yazi, удалённый клиент (только путь, без терминала),
   чат, архив по проекту и всей доске, restore, смена темы, узкий/стековый
   режимы, ноль ошибок консоли.
5. `scripts/auth-check.mjs` — `401` без сессии, `/login`, cookie
   `HttpOnly/Secure/SameSite=Strict`, вход из браузера на loopback, лимит
   неудачных попыток, logout, безопасный `next` и отказ входа по HTTP с
   удалённого адреса.

Сборка проверок идёт в тот же `~/.cache/herdr-planner/target`, не в репозиторий.

## Устройство

```
src/main.rs         запуск, CLI, HTTP/HTTPS, опрос
src/config.rs       конфиг, Argon2/bcrypt, права файла
src/auth.rs         вход, сессии, лимит попыток, middleware
src/board.rs        list/details → задачи, восемь статусов, проекты, итоги
src/theme.rs        colors.toml → CSS-переменные
src/coordinator.rs  разбор вывода `herdr-projects coordinator`
src/app.rs          снимок доски, журнал изменений, кеш деталей
src/server.rs       маршруты, действия, чат, yazi
web/                страница, стили, скрипт, экран входа
packaging/          systemd, .desktop, значок, QML-виджет панели
scripts/            install, open, checks, fixture
```

Своей базы нет. Журнал — это наблюдённые изменения статусов (с отметкой
времени), а не история доски: он пополняется, пока служба работает, и хранится
в `~/.local/state/herdr-planner/journal.json`. Свежая «сделано» живёт карточкой
9 секунд, затем складывается в «Сделано ещё N»; после перезапуска все сделанные
сразу считаются старыми.

## Ограничения

- Вкладки агента и переход в пространство herdr недоступны: это отдельное
  приложение. Кнопки объясняют это, а не притворяются работающими.
- Последний ответ Координатора — хвост его окна (см. выше), а не структурное
  сообщение: у доски нет команды для этого.
- Модель агента на карточке не показывается (в `list --json` её нет); она есть
  в «Фокусе» после `show --task`.
- На удалённой машине yazi не открывается — показывается путь.
- Задачи создаются не здесь, а Координатором (чат) или `herdr-projects add`.
